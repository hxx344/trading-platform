2026-11-20，基线为 v0.73.0（`4b751cf`）。本批分两部分：

- 行情监控金油比（[monitor.md](../monitor.md)「M-2f」）：按 R2 审查，涉及只读公开行情、`monitor.sqlite` 新增一张表、新增一个配置键，以及页面与告警。
- 金油双腿交易（[goldoil.md](../goldoil.md)）：按 R3 审查，涉及下单、执行状态机与新合约 `XAUUSDT`。原油自动规则对 `implicit_reduce` 的处理也一并改动。

## 独立审查

共三轮，每轮新开只读审查者。

**第 1 轮**：行情（R2）与交易后端（R3）分两路审查全量差异，没有 P0 / P1。

| 级别 | 位置 | 问题 | 处理 |
| --- | --- | --- | --- |
| P2 | `web/src/goldoil-form.ts` | 「按当前持仓填入」把同账户 CL / BZ 的原油仓位也填进金油平仓 | 执行器按全部金油任务的实际成交算出净持有（`goldoilHeld`），填入数量取它与账户持仓中较小者，并提示账户另有多少不属于金油 |
| P2 | `src/oil/rules.ts` | 金油的反向油仓让原油规则开仓被 `implicit_reduce` 拒绝，计入失败后规则停用 | 改为等待、不计失败、不停用（L110） |
| P2 | `web/src/OilPage.tsx`、`OilPnl.tsx` | 原油页持仓与盈亏混入金油油腿，页面没有说明 | 加说明「CL / BZ 为账户合计，含金油任务的油腿」，拆分登记为后续 |
| P2 | `test/goldoil.test.ts` 等 | 缺失败场景测试 | 补测：XAU 读取全部失败时原油、海力士不受影响；对冲腿取整为 0 时拒绝；重启接管后按比例结算；只读令牌放行 |
| P2 | `test/monitor-goldoil.test.ts` | 缺失败场景测试 | 补测：429 共用冷却、合约目录失败、写库失败重试、断点续读、进程间 K 线范围校验 |
| P2 | 整体 | 行情与执行混在一份改动里 | 执行部分已按 R3 单独审查并做了两轮复核。`src/http.ts`、`src/read-token.ts`、`tools/mcp/readonly.ts`、文档与若干测试同时含两部分改动，拆开后中间提交无法单独通过检查，因此合为一个提交，提交信息按 R3 写 |
| P3 | 若干 | 变量名、注释、采集未来容差（统一为 5 秒）、告警默认档位、缺口计数、合约目录并发合并、回滚说明 | 均已修复 |

**第 2 轮**：复核第 1 轮修复，没有 P0 / P1。

| 级别 | 问题 | 处理 |
| --- | --- | --- |
| P2 | `goldoilHeld` 每次轮询都重算全部历史 | 按任务与委托的 `version` 缓存，新任务按 `rowid` 增量识别 |
| P2 | 净持有只在算完后截一次 0；结果未知的委托被静默计入 | 每个任务计入后都截 0；结果未知或强制释放的腿标为 `uncertain`，页面留空该腿，提示按交易所持仓手动填写 |
| P2 | 规则被反向仓位阻塞时无限等待，没有通知 | 阻塞满 30 分钟后经发件队列发一次通知，页面显示「被同合约反向仓位阻塞」，状态持久保存 |
| P3 | 合约目录合并读取共用第一个调用方的中止信号 | 改用内部信号，各调用方用自己的信号等待结果 |

**第 3 轮**：复核第 2 轮修复，没有 P0 / P1。

| 级别 | 问题 | 处理 |
| --- | --- | --- |
| P2 | 规则库读取出错时，新增的通知交接让判断链产生未处理的 Promise 拒绝，可能使服务进程退出 | `handOver` 整体兜错，日志每分钟限频，补用例 |
| P2 | 阻塞的起始时间只在预览通过时清除 | 两次受阻相隔超过 120 秒就重新计时并换通知键；因其他原因被拒时清除 |
| P2 | 再次阻塞与 `oilLoops` 通知路径没有测试 | 已补 |
| P3 | 「已发通知」的说法不准确；`uncertain` 的口径没有写进文档 | 文案改为「已交给通知队列」，文档补上口径 |

三轮发现的问题都已关闭，以下登记为后续：

- `goldoilHeld` 每次轮询仍要按缓存的任务编号查一次版本；任务很多时的开销没有测过。
- 原油页的持仓与盈亏拆出金油油腿。
- 通知已生成、但还没交给队列时，阻塞就因别的原因清除，这条通知会丢失（只在队列持续写不进去时才会发生）。
