# 链上折价套利首版审查

2026-11-26，R2。基线为 `c39ff47`（v0.95.0）。范围包括链上报价、Gate 同币身份与盘口、两条路线的测算、行情 IPC、登录后的页面和配置入口，以及页面资源装载。回退到 v0.95.0 不需要迁移配置和数据。

## 独立审查

首轮审查树为 `1f806877`，增量复核树依次为 `b4168d90` 和 `e048cf68`。首轮确认三项 P1。

| 触发条件 | 处理与核验 |
| --- | --- |
| 链上获得 26.999999999999999999 枚，按整枚可卖的数量被浮点数舍入为 27 | 保留原始整数与代币精度，按每条路线的步长精确向下取整，按覆盖数量分摊成本。验证低一最小单位的尾差、最小数量和金额。 |
| 有效深度包含 Gate 市价保护之外的低价买盘 | 按买一价和市场滑点剔除超界档位。永续另核对即时标记价的偏离限制。覆盖界限内外、缺少依据和标记价过期的情况。 |
| 浏览器时钟慢且行情请求响应时间超出剩余时效 | 以本次请求发起的单调时刻计算保守截止时间。覆盖响应到达时已经过期和后续刷新重新计时。 |

第一次增量复核发现 Gate 盘口数量也可能在进入测算器前进位。适配器现在将原始价格、数量、步长以及限额保留为规范十进制字符串。真实读取入口用买盘短一个最小单位的例子验证拒绝足额卖出；适配器还覆盖了两档价格相差一个最小单位、合约乘积末位和原始 JSON 小数。

浏览器启动验证还发现构建生成 65 个页面资源，旧版页面装载器只允许 64 个。文件数上限调至 96，已经用实际构建产物成功加载全部 65 个。单个文件和总字节数仍由装载器检查。

## 验证

- Windows 原生通过 `pnpm check`、`pnpm build:web` 以及链上适配器、Gate、测算、HTTP/IPC、表单和导航的 30 项测试。与接线相关的既有行情深度、行情进程及页面构建产物检查亦通过。
- 1280 和 390 像素宽度均通过模拟行情验收。检验了导航、两条路线、留空与录入成本、换币、无效地址、买盘不足和恢复。页面无横向溢出或 CSP 报错。修复时效后，另在浏览器里将服务端时钟调快 60 秒，给剩余有效期 1.2 秒的回包增加约 2.2 秒延迟。过期回包未展示利润，下一轮正常报价自动恢复。
- 通过公开接口取得 Ethereum、Arbitrum、BNB Smart Chain 三条链的按量路由，并核实 Gate 的 ARB 现货与永续市场。修复后再次以 Arbitrum One 的 ARB 实际贯通链上报价、Gate 充提状态与两个市场的深度测算。没有使用交易账户。

最终独立复核确认上述问题已关闭，未发现剩余 P0、P1 或 P2。以原始公开接口替身贯通两条路线，验证深度恰好足额与少一个最小单位的区别，以及数量和名义金额限额。另用发布包中的运行时文件生成了四个服务组件的指纹。
