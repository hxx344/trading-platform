# DEX 价差与资金费组合缺陷修复

日期为 2026-11-28，审查基线为 `4551e11`（v0.115.0）。发布前主线加入了独立的 MEV 更新，已核对本批代码与该更新没有文件重叠。交付版本为 v0.116.1，父版本为 `aceb4a0`（v0.116.0）。本批范围为 #82、#94、#95、#100、#101、#102。

## 改动前的影响与回滚

按 R3 审查。DEX 的行情时效和按持仓数量取价会影响实盘开平仓判断、持仓展示和历史回测。盘口超过有效期后，采集与就绪检查须识别到具体市场。浮亏和止损按实际持仓规模计入公开盘口冲击。总览只把允许方向达到入场线的配对计入机会。执行器原有的委托、只减仓保护和人工平仓入口继续沿用。

资金费组合使用模拟账本。七天风险窗口应能用足 168 个连续小时收益。存量仓位的风险未知时暂停依赖该预算的规划，状态损坏时保留原始记录和历史，供操作者恢复。错误地继续计算会低估风险，错误地初始化会覆盖模拟资产。

回滚目标为 v0.116.0。既有配置、仓位、采样和表结构可继续读取。若已发现账本损坏，应先备份并恢复有效数据，再启用旧版规划。旧版会重新出现本批涉及的估值、时效和恢复问题。服务器升级由使用者执行，其他开放的改进与新需求继续在各自 Issue 跟踪。

## 修复和首轮审查

| Issue | 本版行为 |
| --- | --- |
| #82 | 持仓估值、止损和回测逐腿按实际数量取价。分别在买卖两侧的公开深度档间插值，插值与降档均标为估算。实盘读各腿剩余数量，保留步长取整和部分成交。 |
| #94 | Lighter 与 Entropy 逐市场保存最后一次有效深度确认的时刻。超过 120 秒立即停用该深度，并限频重订。重新读取、其他市场的推送和行情连接心跳均不能续期。 |
| #95 | 开仓机会数、距开仓、排序和高亮遵循配对当前允许的开仓方向。失联或样本过期时撤下机会，恢复读取后重新统计。 |
| #100 | 以小时收盘为锚点，七天内连续 169 个收盘价可算出 168 个收益，缺小时仍按缺口处理。 |
| #101 | 活跃或已移出配置的标的只要仍有持仓，就须覆盖其波动和共同样本。数据不足时暂停本轮并保留账本、历史和风险未知的提示。 |
| #102 | 分开识别首次运行、记录缺失、坏 JSON 和不支持的结构。损坏记录暂停自动写入，参数和账本各自需要确认恢复。 |

DEX 首轮独立审查发现两项 P1。实际 B 腿可能因数量步长与 A 腿乘数推算值不同，一侧的 100k 档缺失也可能改变另一侧的平仓价并触发止损。本版使用实盘记录里的 B 腿数量，并在每一侧独立选择深度。同轮的一项 P2 为浏览器断线后继续高亮旧机会，另一项 P3 为 L210 沿用旧测试名称，两处均已修订。

对全批固定差异的独立审查又用两组替身复现了五项 P1。

- Lighter 一档从行情摘要切回同价盘口时仍带旧时刻，可能被 30 秒实盘报价门槛拒绝。断档时如果也没有可用的行情摘要，清空整段历史又会丢掉断档前仍然有效的报价。
- 模拟账本即使是合法 JSON，也可能缺少最近一轮中的整户现金和持仓。复核中，这种情况让约 9,963 美元的权益按约 4,767 美元继续规划。只剩历史时，先确认重置账本再重启，还会丢掉参数需要另行确认的状态。
- 持仓缺现价但有历史收益时，拒绝规划后保存参数或重启，页面可能把旧一轮所需资金和步骤重新显示为当前建议。

资金费修订在启动时核对同一事务保存的账户清单，停写不完整账本，并在清账本的事务中保留未确认的参数恢复项。状态页和规划共用持仓现价检查。正常的模拟盘关闭自动执行、设置增删空账户、事务失败和两种恢复顺序均有离线用例。

增量复核又复现一项 P1：残缺账本中若有其他持仓账户同时被改了场所，过早丢弃残缺账本会漏掉第二项异常。本版保留可解析的原记录供账户核验，拒绝展示或使用该账本；单独确认清账再重启，仍须单独确认恢复参数。DEX 的修订把一档来源切换与报价确认时刻分别记录，盘口失效只标记从该时刻开始的空窗，迟到的 Var 报价仍可对齐故障前的有效一档。

对基线到 `f81eb5ab` 的 25 个变更文件完成本地 Codex Security 固定差异审查（`6708f16b-9c37-4ef2-9d82-dfbbfdce5711`）。独立审查核对了登录会话、写请求校验、SQLite 的写入入口和交易执行边界，未发现可报告的安全漏洞。上述模拟资金状态问题按 P1 修复。

最终两路独立复核核对了 `ec3ca524` 的 DEX 和资金费增量。DEX 的 12 项离线用例通过，验证了故障前、空窗中和恢复后三段的时间语义。资金费的 9 项定向用例通过，另以独立内存 SQLite 验证先恢复参数的顺序，重启后原账本与历史保留，自动调度期间行情与风险数据读取次数均为零。本批无待处理 P0、P1 或 P2。

## 验证

Windows 原生 `pnpm check`、`pnpm build:web` 通过。DEX 的 `varlighter`、`lighter-book-top`、`dex-spread-hotpath`、`dex-lead` 修订后合计 100 项通过，另沿用执行器 `dex-live` 与总览表单的 63 项结果。资金费引擎最终 31 项通过，统计与存储等通过 11 项，另沿用求解器 13 项与页面表单 9 项。合计 227 项，包含按腿或单侧缺档、边界两侧、跨市场停推、正常重连、模拟账本两种恢复顺序与失败时原始记录逐字节保留。

Chrome 在 1280 和 390 像素宽度走查两个模块。DEX 用四组确定的替身数据核对两种总览的计数、顺序、旧设置兼容与过期，浏览器离线后机会数消失，联网后恢复。资金费组合用临时损坏的 SQLite 记录走正常页面与写接口。取消两种恢复均保留原记录，确认重置账本仍要求单独恢复参数。保存七天窗口后，四个标的各取得 168 个小时收益，生成首轮规划。两个模块均无页面脚本或 CSP 错误，表格在窄屏面板内滚动。

另用保留真实页面、HTTP 处理和模拟引擎的本地行情替身撤去全部现价。两个账户仍有持仓，当前权益和规划为空；页面可按轮次查看历史。修改并保存持有期后，当前建议仍不可用。恢复现价后引擎完成第二轮，四个标的各保留 168 个小时样本。

行情与成交使用替身，未连接真实账户或交易所，未进行服务器部署。生产环境的实际停推频率、实盘净盈亏与真实历史回补耗时未作测量。
