## 审查结论

### 第一轮

独立只读审查。审查者的上下文与作者隔离，只拿到：仓库、差异范围 `4583893..8d0e7f1`、`docs/code-review.md`、相关 LESSONS 条目和待核查重点。

结论：没有 P0、P1；P2 三条，P3 四条。

| 级别 | 问题 | 处理 |
| --- | --- | --- |
| P2 | Ondo 账户没有本机进程锁。`mm.initialize()` 会在写入租约之前，按会话记录撤掉所有 `tpo-` 挂单。同一个 Key 在本机起第二个进程时，会撤掉第一个进程的实盘挂单 | 有 Key 时，先按 keyId 摘要加 `holdAccountLocks`，再 initialize。加锁失败时服务不启动，报错只带末四位；锁在 close 时释放。跨机器使用同一个 Key 写进 ondo.md 第 1 节「不做」。补测试 |
| P2 | 一侧不满 100 档时，当作整侧都拿到了，可能静默高估份额（L093） | 覆盖距离一律按返回的最远一档计算，覆盖不足时页面标出；改测试 |
| P2 | 停服时要等进行中的盘口读取（最长 5 秒）结束才开始撤单，可能超出排空期 | 收到停止就关闭采集客户端，中止进行中的读取，同时开始撤单（最多等 15 秒）。补测试：读取挂起时，停服在 1 秒内结束并关闭客户端 |
| P3 | 采样间隔没有扣除读取耗时 | 每步时长减去本轮耗时，最少 250 ms；补测试 |
| P3 | 页面发起的读取和采集循环共用同一次请求时，循环少记一个样本 | 加 `record` 标志，共用时照记样本；补测试 |
| P3 | stop、cleanup、recovery/discard 收到空请求体时报「未知字段」 | 空请求体按 `{}` 处理；文档写明仍须带 JSON 的 content-type |
| P3 | 读 `credentials.key` 时先读入再检查长度 | 子进程先用 stat 检查大小 |

审查者核对过、没有问题的部分：
