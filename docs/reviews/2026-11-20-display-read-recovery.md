# 资产读取与行情首轮采集失败

基线为 v0.72.0（`1b304c2`）。按 R3 审查，因为同一次资产同步既能更新估值，也可能发现账户的只读权限已经撤销。

资产、持仓和监控关联交易遇到同一范围内的写入时，应丢弃写入前发出的应答，在原读取时限内重新向服务核对一次。切页取消、会话失效、换账户或监控换代应继续拦住旧请求。失败后有上次结果的页面保留旧值并标记，无结果的页面显示读取状态或失败原因。

海力士、原油和 Anthropic 监控需要区分等待首次报价与采集已经失败。价格与 K 线沿用原始采集时刻，历史缺口和过期提示按行情时间计算。影响面限于页面展示读取与采集器已有状态的只读接口。生产现场的上游连接状况须由实际采集记录确认。

失败时可用 `sudo bash install.sh --version v0.72.0` 回退，配置、账本和行情库均可沿用。

## 独立审查

首轮核对从基线到 `36fd5bc` 的固定差异。展示读的写后核对与页面状态按 R3 核查，行情接口沿用原采集器生成的简短原因。后续分别复核 `db38e8e`、`2a79a7e` 和最终源码树 `4bff16c` 的增量。

| 级别 | 触发条件 | 处理 |
| --- | --- | --- |
| P1 | 成交、每日波动或净资金流读取失败后再读，原数据还在，错误提示却提前消失 | 重试期间继续标明读取失败及实际保留的结果，成功后清除 |
| P2 | 例行同步完成后，上一轮读取迟到返回 503 | 同范围的短时失败也可补读一次。拒权和取消直接结束旧请求 |
| P2 | 选择文件只预览原表，却会中断其他账本读取 | 依据实际提交的 `apply` 区分预览和应用，确认导入继续撤销旧账本的应答 |
| P2 | 一次性预览超时或正文损坏时提示自动重试，页面还会触发账本刷新 | 预览失败提示重选文件，可以重选同一文件。会话失效和确认导入结果未知仍进入原有处理 |

最终独立复核已关闭以上问题。Codex Security 插件未识别本机工作树，账户隔离及拒权路径由独立源码审查和定向测试核对。

## 验证

Windows 原生执行了 `pnpm check`、`pnpm build:web` 及展示读取、行情采集、K 线缓存和成交相关的 Node 测试。首批 57 项通过，后续仅重跑受影响项。并发用例覆盖同步先结束、切页取消、解码中写入、补读中再次写入、换账户、会话失效和明确拒权。海力士替身在首轮返回 429 后恢复，真实 HTTP 接口先返回采集器的限流原因，恢复后返回新的有效报价与 K 线。

生产构建在 1280 和 390 像素宽度通过 Chrome 替身验收。两种宽度下，资产同步期间离页均发出两次持仓读取并取得结果。报价失败时显示上游限流原因、缓存的实际采集时间及两小时过期提示，恢复后在下一轮自动显示实时报价。未出现页面异常、CSP 违规或横向溢出。线上账户、交易所与服务器未参与本次验收。

最终页面构建在两种宽度还核对了原表预览坏正文后连续选择同一文件两次，账本、历史和状态均无额外读取。每日波动与净资金流分别覆盖首次失败、持有旧结果时失败、重试尚未结束及成功恢复。
