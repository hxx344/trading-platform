## 验收与复用

五个隔离 runner 各自建立本组的真实部署前态。单进程迁移、页面导入及连续四次页面更新在同一 runner 内检查进程、登录会话和固定包。组件更新与故障回退在各自 runner 上使用真实端口和 PID。新旧拓扑及安装器记录偏离使用历史正式包。原四个故意损坏的包各保留 8 秒失败探针，恢复版本均走 90 秒健康预算。

只有主线推送查询可复用的手动 CI。核对仓库、工作流、提交、运行尝试、Ubuntu 镜像版本和架构，以及五个实际验收步骤的成功状态。资料缺失、接口不可读或曾跳过任一验收步骤时，主线重新执行。手动完整运行继续顺序执行 `test-install.sh`。普通提交原有的部署路径过滤继续生效。

Windows 原生运行验收复用及发布门禁的 6 项测试，并通过后端与测试类型检查、工作流 YAML 解析、Git for Windows Bash 语法和差异检查。复用回归覆盖缺组、步骤被跳过、不同提交、仓库、尝试或镜像、查询失败，以及强制执行的手动验收。
