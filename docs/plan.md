# 统一交易平台：实施方案 v1.0

2026-11-12 用户决定：统一交易平台改在独立仓库建设。第一阶段只做两项核心功能并接真实账户：

1. ASTER 配对的保证金平衡划转；
2. ASTER 配对的 ADL 应急处理。

其他功能（原油双腿、ANT、期权、Aero 等）以后按需在本仓库逐个验证接入，第一阶段不接线。

## 1 已定决策

| 事项 | 决定 |
| --- | --- |
| 项目形态 | 独立 GitHub 仓库 `trading-platform`（public），自带 `install.sh`、systemd、数据目录与正式发布；与工作台在同一台服务器并行运行，互不读写对方的库 |
| 接管方式 | 按配对手动切换：用户先在工作台停止并删除该配对，再在本项目启用；启用前的检查见第 4 节。切换后由本项目独占这三个账户的划转与减仓写入。工作台单账户普通开仓不得再使用这些子账户 |
| 界面 | 只监听 `127.0.0.1` 的简易网页（配对状态、两账户余额、划转与 ADL 记录、启停、ADL 人工操作），通过 SSH 隧道访问；告警走飞书 |
| 实现基础 | 以工作台 `platform/executor`（TypeScript）为底，源提交 `62b6067`。划转与 ADL 状态机、存储、单写者租约原样带入；真实 ASTER 连接器参照工作台 Python 实盘版（`modules/aster/trading`）补写 |
| 共享写者登记 | 不使用。工作台的 `execution-control.sqlite` 只服务工作台；本项目靠“切换前停用工作台配对 + 启用检查 + 本进程单写者租约”保证唯一写者。执行器原有的登记注入点保持为空 |

## 2 业务规则

规则以执行器现有实现为准（`docs/executor.md`《关键语义》），其中 ADL 的四项是 2026-11-11 用户已定的决定，与工作台 Python 版不同：

- 完成后自动结束：两账户事件标的多空总量相等即完成；有结果未知的原单时观察 10 分钟后自动关闭（Python 是保持 hold、无期限观察）。
- 时限 1800 s 只累计减仓中（active）的时间；停止后可在页面“重新开始自动减仓”（Python 计入受阻时间、停止后无出口）。
- 减仓单为只减仓市价单，单批名义上限默认 1000 USDT。
- 残差小于最小下单量记为完成（Python 一直受阻）。

划转规则与 Python 一致：同一主账户下两个子账户，只划 USD1。
- 触发与金额：两侧可用余额之差严格大于门槛（默认 10）才划转，从多的一侧划到少的一侧。金额取以下几项中的最小值：差额一半、单次上限（1000）、转出侧可提额、转出侧可用减保留额。
- 保留额与冷却：保留额 = 权益 × 保留比例（0.05），冷却 30 s，最小 1。
- 结果未知不重发：nonce 过期（最后更新 + 120 s）后读一次流水，打标签结清。

第一阶段要补齐的差异：

- 绝对现金保留额（Python 的 `long_reserve`/`short_reserve`，默认 0 即关闭）：转出侧保留额取 max(权益 × 比例, 该侧固定保留额)，配置项 `longReserve`/`shortReserve`（已完成）。
- 余额与流水用各子账户自己的凭据读取；主账户只读子账户列表、发划转（与 Python 一致；“主账户直接读子账户余额”未经实测，不依赖）。
- 双向持仓模式下减仓单不带 `reduceOnly`、按 `positionSide` 减仓；单向（BOTH）才带 `reduceOnly`（与 Python 一致）。

## 3 架构

```
trading-platform/
  src/            执行器（来自 platform/executor）：存储、租约、划转、ADL、持仓展示、页面
  src/aster/      真实 ASTER：签名（EIP-712，已在真实划转探测中用过）、请求预算、
                  划转 / ADL / 持仓连接器、用户推送（ADL 即时发现）
  src/service/    服务入口：配置与密钥文件、启用检查、飞书发件箱
  probes/         真实接口探测脚本（ASTER 划转）
  deploy/         install.sh、systemd 单元
```

运行形态：一个 Node 24 进程（systemd 服务 `trading-platform`，系统账号同名），数据在 `/var/lib/trading-platform`，配置在 `/etc/trading-platform`，程序在 `/opt/trading-platform`。

- 配置 `config.json`：密钥文件的绝对路径 `secretsFile`、配对列表（`id`、主账户和多空子账户的凭据名、划转参数）、本机端口（默认 4720）、请求预算。1–20 个配对，同一子账户只能在一个配对里。
- 密钥 `secrets.json`：每个 ASTER 账户的 `user`、`signer`、`privateKey`，以及飞书机器人 `webhook` 与签名密钥；两个凭据名不能指向同一个钱包。文件属服务账号，权限 600，最大 64 KiB；启动时校验私钥能推出 signer。
- 请求预算：ASTER 按出口 IP 计请求权重，工作台 ASTER 模块共用同一 IP 并自限每分钟 1800。本项目默认每分钟最多 600，可配置；ADL 读取与减仓优先于划转。
- 飞书：发件箱落在独立的 `notify.sqlite`，首次启动从当前事件开始（不补发历史）；单次超时 10 s、失败指数退避（最长 5 分钟）、保留 7 天，同一持续问题 30 分钟内只发一次；发送失败不影响划转与 ADL。告警项：划转结果未知与结清依据、已启用配对受阻或提示持续 10 分钟（及恢复）、ADL 发现、受阻、停止与完成、服务启动与停止（含租约丢失、处理循环连续失败）。未配置机器人时只写日志。
- 用户推送：每个子账户一条 ASTER 用户推送（listenKey，30 分钟续期、23 小时 50 分计划重连、0.5–30 s 退避），只用来更快发现 ADL；断开时按 60 s 一次的强平历史扫描兜底。
- ADL 只处理已启用的配对（以及停用前仍有未结束事件的配对），历史扫描从配对启用时开始，不回看启用前。

## 4 切换与回退

切换一个配对：

1. 执行 `sudo bash install.sh --import-workbench`：从本机工作台导入配对设置（保证金平衡各项、ADL 自动减仓与单批上限）、三个账户凭据和飞书机器人，登记后默认停用。只读工作台数据。也可以手写 `config.json` 后执行 `sudo bash install.sh`。配置里的 `adl` 只在配对首次登记时作为初始值，之后以页面为准。
2. 在工作台暂停并删除该配对，确认工作台“账户写入”里这三个账户没有未结清的划转。
3. 页面点“启用”。启用前检查以下各项，任一不满足就拒绝并说明原因：
   - 凭据：三个账户凭据有效，主账户能列出两个子账户，且子账户未冻结。
   - 外部划转：两个子账户最近 10 分钟的流水里没有不属于本项目的 `SUBUSER_ASSET_TRANSFER`。这是检测工作台配对是否仍在运行的旁证。
   - 外部减仓单：两个子账户没有客户订单号以 `adl_` 开头的挂单。这类挂单是工作台 ADL 遗留的。
   - 两侧对冲：两个子账户合计每个标的的净持仓为 0。ADL 只从启用时开始扫描，停用工作台到启用之间发生的 ADL 由这一项拦下，须人工处理到两侧一致再启用。

   配置里删掉的配对在服务启动时自动停用；改了账户的配对重新登记为停用。
4. 启用后先观察一轮划转。

回退：在本项目停用该配对。停用前须确认没有未结清的划转与未结束的 ADL 批次，页面会提示。之后在工作台重建配对。本项目的库不回写工作台。

## 6 尚待实测（接真实账户时确认）

- 子账户列表行是否带钱包地址（2.6b 实测能核实归属，但未记录字段）；不带时按各子账户自己的 `accountId` 对应。
- `positionRisk` 的零仓位行是否带 `updateTime`（缺失时按 0 处理，执行器视为未证明已反映）。

- nonce 有效窗口按 120 s 计（ASTER 文档 ±60 s，未实测）。
- ADL 减仓单回报的 `updateTime` 是否不晚于持仓 `updateTime`（若晚于，每批多等 120 s）。
- `forceOrders` 查询跨度上限（重新启用时扫描从启用时刻开始，正常运行窗口约 2 分钟，不依赖长跨度）。
- 网关拒绝（HTML 429/403）与 `X-MBX-USED-WEIGHT-1M` 响应头的真实表现（替身已覆盖）。
- 本服务为同一子账户申请 listenKey 是否会让工作台已有的推送失效（工作台停用该配对后已不依赖，但同账户其他用途需留意）。
- 高负载下流水入账延迟（2.6b 实测 50–206 ms，仅 2 个样本）。

## 7 已知限制

- 请求额度：每个配对空闲时每分钟约 260 权重（两侧余额每 5 s、持仓显示每 15 s、ADL 历史每分钟）；未配置 `budget` 时按配对数自动取值，最多约 6 个默认配对，再多需调大 `checkIntervalMs`。
- 停用配对即停止该配对新的 ADL 检测；停用期间发生的 ADL 不处理，重新启用前接管检查要求两侧每个标的净持仓为 0。
- 从工作台导入后、在工作台删除配对之前，两边同时运行：本服务已为停用的配对建立子账户推送并读取余额与持仓（计入同一出口 IP 的请求权重），但不划转、不检测 ADL。两边都不注销 listenKey，推送互不影响；配对多时两边合计权重是否逼近 IP 上限待实测，建议导入后尽快逐个切换，或用 `--pairs` 只导入马上要切换的配对。
- `--import-workbench` 在导入后的配置检查或启动失败时恢复导入前的 `config.json` 与密钥文件（含属主与权限）；回退到 v0.1.0 前须先移除配置里的 `adl` 字段，旧版本不认识它。

- EIP-712 签名（`src/aster/eip712.ts`）是本仓库的零依赖实现，已与 ethers 及 Python `eth_account` 逐字节对照，并在 2.6b 真实划转中用过；它不是常量时间实现（私钥只在本机签名，远端观察不到时序）。以后如引入运行时依赖，换成经过审计的库（如 `@noble/curves`）。
