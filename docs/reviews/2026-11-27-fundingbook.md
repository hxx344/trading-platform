# 资金费组合第一期（只读规划器与模拟盘）

日期 2026-11-27。基线为 v0.104.0，范围是新模块 `src/fundingbook/`、`src/service/fundingbook.ts`、`web/src/fundingbook/`、`scripts/dev-fundingbook.ts`、五个测试文件，以及 `src/monitor/perpetual.ts`、`src/service/main.ts`、`src/http.ts`、`src/shell-view.ts`、`web/src/{App.tsx,route-parse.ts,workspace-nav.ts}` 的接线，文档见 [fundingbook.md](../fundingbook.md)。模块的终点是下单与划转，按 R3 流程做；这一期本身不读账户、不向交易所发写请求、不接触凭据，新建 `fundingbook.sqlite`（首次建库，没有迁移）。回滚版本 v0.104.0，回滚前不需要任何操作。

## 独立审查与处置

第一轮两路只读审查（后端、页面与文档），上下文与作者隔离。后端审查确认：模块只引入 `node:sqlite`、`node:path` 与模块内文件，对外只经合约价差监控的 4 个只读方法；`perpetual.ts` 的读取器重构等价；`/api/fundingbook/*` 在登录与写请求校验之后；规划与模拟盘在同一事务落库，求解让出事件循环期间的改参数、重置由 `revision` 挡住。

| 发现 | 修正与验证 |
| --- | --- |
| P1，增量刷新只从上次读到的时刻往后读，晚发布的结算与整点 K 线被永久漏掉，年化与模拟盘资金费静默偏低 | 每次刷新回看 2 小时（不超过读取器的段长），写入是覆盖写。引擎测试断言重读的起点；把回看去掉时该测试失败 |
| P1，只有超预算一侧有迟滞，价格一跌就加仓、涨回又缩；当前仓位按各场所自己的价格折名义金额，基差变化让求解器只调一条腿 | 求解加 3% 的不交易带；同一标的各账户用同一个参考价折名义金额与数量。引擎测试在价格 −1.5% 到 −2%、基差 ±0.15% 下断言不出订单、数量合计为零；分别关掉不交易带、参考价时该测试失败 |
| P2，保存参数中止在途读取被记成失败并退避 5 分钟 | 中止后不写覆盖范围。测试在读取在途时保存参数，断言没有错误；去掉修正时失败 |
| P2，模拟盘里有持仓的账户可以换场所，持仓按另一场所的价格与资金费计 | 返回 409，先重置模拟盘。有测试 |
| P2，报价不查新鲜度 | `liveQuotes()` 把过期的标记价与盘口置空；复核确认各场所的报价都带时间戳，且只有本模块调用它 |
| P2，相关性各对分别取样、缺样本记 0，矩阵可能不是半正定 | 只用全部标的共同的整点算相关性，共同整点不足时去掉让大家对不上的那个标的。有测试 |
| P2，去掉小腿后不复核预算，可能小幅超出 | 复核并按比例缩回。随机起点测试 40 组、带与不带不交易带，断言预算、合计为零与总名义上限 |
| P2，文档说不可用的腿「不参与」，实际会把有持仓的标的整笔平掉 | 改代码：有持仓的腿用不了时整个标的保持不动。求解器与引擎各有测试 |
| P2，页面文档说表单校验范围，实际只查格式；验证记录把服务端的拒绝写成表单拦下 | 文档改成实际行为 |
| P2，保存成功后表单被旧值盖回；`parseState` 不查 `venues` 与 `collect.errors`；本金为 0 时显示 Infinity；文件头注释节号指错 | 均已修；保存一项在浏览器里复验（保存后 200 毫秒与 6 秒都是新值） |

第二轮新开审查者做增量复核：第 4 至 7、9 项关闭，没有 P0、P1，新提 7 条 P2，均已修：

- 回看让单次资金费查询最长达到段长加 2 小时，停了约 94 到 96 小时后会被读取器拒绝：起点再与「现在减段长」取较大者，补了停将近四天的测试。
- 保持不动的标的在起点清零与起点缩放两处没有排除：两处都跳过，补了测试。
- 没有订单时几乎每轮仍出划转：没有订单且每个账户现有权益都够它的所需资金时不出划转，测试断言目标不变的一轮步骤为空。
- 共同整点不足时按样本最少去标的会留下过期的那个：改为去掉让其余标的共同整点最多的那个，补了测试。
- 保存后写回表单的修改被 effect 用旧值盖掉：改为只在服务端的值变了时跟随。
- 文档两处与代码不符（保持不动的例外、最小划转额与最小订单额）：已改。

第二轮这 7 条的修正由测试与浏览器复验核对，没有再做第三轮独立审查。

登记未处理（P3，见 fundingbook.md 第 10 节末）：没进风险模型的标的在保持不动期间按零波动计；库里的参数或模拟盘 JSON 读坏时静默回到默认值或新建；`plan`、`paper/reset` 不拒绝多余的键。`perpetual.ts` 新增三个方法没有单独的测试，由引擎测试经替身入口间接覆盖。
