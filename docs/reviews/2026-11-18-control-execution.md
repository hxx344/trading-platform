# 控制面与交易执行面独立更新

2026-11-18，R3。基线为 v0.63.0 的 `11d083f`。范围包括发布包、安装器与 systemd 单元，两个 HTTP 入口、在线更新交接、配置核对、更新确认文案和相关验收。使用本版安装器指定 v0.63.0 可以恢复单进程，配置和数据库可沿用。

## 审查与处理

独立审查分为浏览器与执行接口、部署与回退两路，首轮固定候选为 `ab2c645`。修订版按 `82c0333`、`5fed6cf`、`25ea47d` 的固定增量复核。各次候选在验证分支上验收。

| 经核实的问题 | 处理与证据 |
| --- | --- |
| P0，共用服务 UID 时无法保证交易凭据和进程信号的隔离 | 控制面改用独立 UID、私有更新目录。执行器持有私有套接字，控制面通过专组连接。root 助手核对请求属主 |
| P1，写请求失去上游应答时返回 503，可能使旧页面丢弃请求号 | 代理结束未知写入的连接。使用页面的 `api()` 与 `RequestIds` 验证 POST、PUT 保留原号，真实业务拒绝仍有状态码。另补缺 Host 和 gzip SSE 断线清理 |
| P1，工作台导入后，安装记录的旧配置摘要会触发额外执行重启 | 安装器与运行进程核对实际载入的配置、密钥和登录口令。安装后再核对进程、监听和配置摘要 |
| P1，控制面回退可能恢复旧端口而执行器使用新端口。仅更新 root 助手也曾导致执行进程重启 | 回退根据实际生效配置重新生成监听设置并验证。发布包单独识别 root 助手文件。systemd 验收覆盖上述两种更新 |
| P0，自定义更新目录误指向程序树可能改变程序目录权限 | 安装器在调整更新目录权限前检查与程序、数据、配置及交接目录是否重叠。安装测试包含自定义路径负例 |
| P1，自定义更新目录的父目录可能在安装后被 root 助手拒绝 | 将安装前置条件与助手运行时对齐。真实 systemd 验收加入父目录权限、属主、链接、缺失与相对路径的负例 |
| P1，曾降回单体的服务器再次在线迁移时，新目录可能留下更早的历史回执 | 优先处理当前待办，再按任务时间与编号选择旧、新助手的结果。浏览器可以继续跟踪原任务 |
| 部署验收发现监听器可能漏掉已存在的请求、配置缓存和旧安装基线需要恢复 | 对提交的请求按文件存在触发，先改名取走再校验。无参数安装测试与一次性 systemd 测试覆盖迁移、重复运行及回退 |

## 业务连续性

Windows 原生模拟验收启动独立控制与执行进程。两腿首腿、保证金划转和 ADL 第一批均处于在途状态时切换页面包，再杀掉控制面。控制面离线期间通过只读 SQLite 连接看到原三条业务记录全部结清。两腿各成交 1，划转 100 USD1，ADL 两批合计 0.02 BTC。重启后用原会话和未读到回包的原请求号取得同一笔任务，模拟交易所的指令计数、执行 PID 和租约代次均符合预期。[连续性测试](../../test/control-continuity.test.ts) · [传输测试](../../test/control-transport.test.ts)

浏览器以生产前端构建连接本机替身，1280 和 390 像素宽度均能查看版本和确认区的组件更新说明。移动端文档宽度为 390 像素。控制台记录的是未启用的可选模块探测和 favicon 的 404，未见 CSP 拒绝。

本地 Codex Security 的固定差异扫描入口两次报告无法解析 Git 工作树 HEAD，未生成托管报告。本地 Git 与 Git 连接器均能读取该仓库，以上鉴权、账户权限及 root 路径结论来自独立的固定差异安全审查。交易验收使用模拟交易所，服务器系统测试使用一次性 Ubuntu runner。
