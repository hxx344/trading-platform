# 2026-11-26 开放缺陷修复

开发基线为 v0.91.0（`f5cfa68`）。发布前已合入其后发布的 v0.92.0（`47758a1`），正式版本的回滚目标为 **v0.92.0**。本批按 R3 审查，涉及 MEV 实盘启停、DEX 模拟状态的持久化和只读令牌的请求目的地。

## 变更前的范围与回滚

- #87。停止 MEV 时作废所有更早且尚在核对的开始请求。影响引擎内存中的授权和核对结果。过时操作应返回冲突，服务停机期间应拒绝开始，已提交的交易仍须结清。回滚后须避免多个会话同时操作启停。
- #76、#81、#82、#83。使 DEX 模拟仓位、冷却、成交与事件一同提交，以实际判断时刻、盘口证据和询价数量决定成交。数据库写失败应保留上次提交的状态。历史证据不足时明确采用保守口径。新增的样本证据须允许旧版打开数据库，回滚后旧版重新使用原来的回测口径。
- #88、#89。本机缓存须能确认样本、参数和费率来自同一平台。零条明细仍应返回完整收益摘要。回滚到 v0.92.0 时使用旧目录，新版按来源保存的数据与旧目录分开。
- #71、#77。保证金异常达到阈值后保存待补报告。Anthropic 跨版本行情协议须在写缓存之前核实 Binance 计价单位。故障和混合版本期间应能辨别缺报或缺价，回滚恢复旧协议。

验收使用离线节点、受控时钟和临时 SQLite 库。真实账户操作与服务器升级由账户持有人执行。产品需求和独立的测试改进提案保留在各自的 Issue 中。

Codex Security 的托管差异扫描未能解析 Windows 工作树。独立审查按固定 Git 对象核对鉴权入口、签名发送、已有交易结清和只读令牌的请求目的地。该插件的补丁风险评估工具已校验最终整合差异 `47758a1..94baf40` 的执行与凭据边界评估。对应 `git diff --binary --full-index` 的 SHA-256 为 `11c930dad086b653cdeac6ead68f3ebf48d907ef96082df04d8bb074027d2be3`。

第三轮告警复核确认跨页修复有效，同时指出执行日志本身读失败时可能漏掉短暂恢复。重新按数据来源确定判据：余额读数决定异常开始与恢复，划转事件决定连续无进展的时长，通知游标只决定哪条消息已经持久交接。只要余额可读，就观察恢复、重试已确认的补报、处理停用或移除。只有核实事件进度后，才按时长新发或重复发送异常。用执行日志不可读、余额先恢复又失衡的场景验证。
