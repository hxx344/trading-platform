## 第 1 轮独立审查（基线 25665d9，未提交改动）

结论：P0、P1 无。已核实无问题：主文件只在服务进程里写（打开时载入、`save`、持仓服务停下后的 `adoptPending`）；第三方持仓服务 `stop()` 排空写入队列，`paperUpdate` 先等载入，载入用的 Promise 同步设上；重建取 `store.get()` 的合并后状态，计时器链调用时才取 `paper`；载入中途 stop / stop→start / stop→start→stop 推演后只有一个实例、不漏停，`settled()` 等载入结束。root 侧读取照 M-3d-2：目录属主身份、空环境、`cwd /`、lstat 不跟随链接、1 MB 上限、解析器报错不透传、输出过滤控制字符。写入方：数据目录属主身份、`assertDedicatedDataDir`、主文件与待载入文件须为本账户普通文件、umask 077、`wx` + 0600 临时文件再改名、stdin 1 MB 上限、输出只有计数与 id。合并规则两处一致；rejected 与 `stuck` 每个文件只记一次日志，写入方每次写都是新 inode，不会永久挡住后来的导入。导入助手写入顺序、失败时配置不改、只导入持仓记录时不重启、结果以写入方为准、channel 要求和 `monitor` 一起发；`install.sh` 参数配对、版本检测与 `--data-dir` 已接上。页面勾选联动、请求体、确认框两种说法准确。

| 级别 | 问题 | 处理 |
| --- | --- | --- |
| P2 | 载入读完待载入文件后、删除或改名之前，写入方换上的新待载入文件会被这次载入删掉或改名为 rejected，新记录丢失而导入已回答成功 | 载入先认领：把待载入文件改名为 `perpetual-paper-positions.import.loading.json`，之后只对认领文件读、删、改名；中断留下的认领文件优先处理，打开时依次处理认领文件和待载入文件（各至多一次），`opened` 改为数组。测试：遗留认领文件与新待载入文件同在时依次载入；认领期间放入的待载入文件不被动，留给下一次载入 |
| P2 | 载入挂起时的停止 / 重开、页面写入与载入重叠都没有用例（原用例靠 409 重试，证明不了重叠） | 新增采集器用例：可控存放替身让 `adoptPending` 挂起，断言挂起期间的页面写入在载入完成前不回答、之后落在重建的服务上（版本已变，409，不生效）；stop→start→stop 时 `settled()` 等载入结束、重建的服务不启动；stop→start 时载入后只重建一次并照常运行。去掉 `stop()` 里对载入的等待后该用例失败 |
| P3 | 写主文件失败（如磁盘满）也把待载入文件改名为 rejected，恢复后不会自动载入 | 返回 `deferred`，保留认领文件并记为 `stuck`（同一文件不再每秒重试），重启后载入；测试用占住临时路径的目录模拟写失败 |
| P3 | 写入方与 `inspect` 把主文件已有的待载入记录再计一次，预览偏大，可能误判超限 | `current()` 先去掉待载入文件里主文件已有 `id` 的记录；测试覆盖 |
| P3 | 载入日志：全部过期时写“本服务都已有”；删除失败时仍写“已删除” | 结果带上计划的原因与是否删除、是否改名，日志按情况措辞 |
| P3 | 合并前不清过期的已结束记录，采集关闭期间可能误拒本可通过的导入 | 计数不含过期的已结束记录（`id` 仍保留，免得同一记录复活），合并时先按保留期去掉它们；测试覆盖 |
| P3 | 须同时启用或补全行情监控时，勾选项仍写“不重启服务”（Var token 一项同样） | 两项勾选文案按是否须勾选行情监控分别写“随行情监控一起重启后载入 / 生效”或“不重启服务” |

## 第 2 轮复核（新的审查代理，只看修复）

结论：第 1 轮 7 条全部关闭，文档与代码一致；无新的 P0–P2。已核实：认领各分支（ENOENT 无副作用；认领、读取、超限、写入、删除失败）的 `stuck` 与 `waiting()` 标识一致，同一文件不每秒重试，文件移走或换上新的后会再处理，不会永久卡住；打开时的循环至多两次；合并前去掉过期记录后与第三方 `prune` 判断一致（超过 100 条已结束整批拒绝，`prune` 的截断不生效），`requestId` 冲突口径相同；写入方 `merged.add` 与去重后的待载入记录一致。

| 级别 | 问题 | 处理 |
| --- | --- | --- |
| P3 | 写入方不读认领文件：写主文件失败、认领文件留到重启期间，预览与上限预检不含它的记录，重启后可能整批改名为 rejected | `current()` 按服务载入的同一规则先把认领文件合并进主文件的记录再计数（读不出的认领文件不计，服务会把它改名）；测试覆盖 |
| P3 | `adoptPending` 抛出意外异常时没设 `stuck`，会每秒重试并记日志，与日志里“重启后再试”不符 | 存放内用 `attempt()` 包住载入，异常时把当前文件记为 `stuck` 并返回 `deferred`；打开时同样经它 |
| P3 | 卡住分支只测了写主文件失败 | 补“改名为 rejected 失败”：认领文件留着、`pending()` 为假、日志写明留在认领文件，重启后依次载入认领文件与待载入文件 |

第 2 轮的三处修复都是 P3 级的局部改动，由作者核对并补了测试，没有再开第 3 轮审查。
