# 前端 F1：服务页迁到 React 预构建（R2）审查记录

- 日期：2026-11-12
- 范围：见 [docs/frontend.md](../frontend.md) F1。
  - 服务页从内联 HTML 字符串（`src/page.ts` 的 `ASTER_PAGE`）逐项迁到 `web/`（React 19 + Vite 8，预构建）。
  - `src/web-assets.ts` 在启动和 `--check-config` 前载入构建产物；`/` 与 `/assets/*` 都要求登录；页面 CSP 不再放行内联脚本和样式。
  - 发布包带上 `web/dist`，CI 与发布流程先构建页面。
- 等级：R2（页面与静态文件托管；划转、ADL 与接口均不变）。
- 回滚：`sudo bash install.sh --version v0.4.4`；数据库与配置格式不变。

## 第一轮（独立审查）

无 P0/P1。逐项核实成立的部分：
- `/assets` 鉴权与路径处理（内存 Map 按名查找，穿越与编码路径 404）。
- CSP 无需 `unsafe-inline`：React 用 `el.style` 写样式，不受 style-src 限制。
- 功能与旧页面逐项一致（文案、确认提示、导入轮询语义、请求号 key）。
- 安装失败时保留旧版本。

| 级别 | 问题 | 处理 |
| --- | --- | --- |
| P2 | 结果未知的请求号一直保留，之后同一动作误当重放（启用→停用→再启用、重新开始→再停止→再重新开始变空操作）；旧页面原有 | 已修：页面显示已生效即作废该编号；重新开始的输入带重启次数 |
| P2 | 从后台恢复后第一次读取期间，旧数据不标陈旧 | 已修：超过两次刷新加读超时也算陈旧，并单独提示 |
| P2 | `api.ts` 错误分类无单测 | 已修：替身 fetch 覆盖网络错误、超时、读响应体中断、4xx/5xx、2xx 不可解析 |
| P3 | 2xx 响应体不可读被当失败 | 已修：按成功处理并刷新 |
| P3 | 扩展名按普通对象下标取类型（`x.constructor`、无点文件名） | 已修：`Object.hasOwn`，且必须有点 |
| P3 | 会话失效提示不复位；持仓提示「刷新失败」用词不准；文档 CSP 少 `font-src` | 已修 |
| P3 | 5xx 算有应答（与旧页面一致）；导入 POST 无请求号；离线时暂停轮询（隧道下仍可达）；package.sh 不检查产物是否最新；`index.html` 检查为启发式 | 登记 |

## 第二轮（复审修复差异）

确认第一轮 3 个 P2 都修对了：请求在途时刷新生效不会残留编号；结果未知且未生效时仍沿用原编号；没有发现重复执行。

| 级别 | 问题 | 处理 |
| --- | --- | --- |
| P2 | 「2xx 不可读按成功」也作用于读取：返回 `{}` 当作状态，整页报错；导入 POST 拿到 `{}` 后误报助手无响应 | 已修：只对写入兜底；读取不可读按读取失败（不带状态码）；导入应答缺编号提示结果未知；补测试 |
| P3 | 启用结果未知且已生效，但页面看到前配对又被服务端停用（启动按配置停用、账户更换），再点启用会被当作重放，多点一次 | 登记：只多一次空点，不会重复执行 |
| P3 | 重新开始的 effect 与 input 中的重启次数重复 | 保留，无害 |
