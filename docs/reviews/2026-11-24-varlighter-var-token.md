## 第二轮复核

范围：提交 3cb9b94 相对 6da41d3，新开审查者。结论：没有 P0、P1。P2 3 条、P3 3 条，全部已修（提交见本文件所在的提交）。第一轮 P2 的第 1、4 条修复成立，第 2、3 条部分成立，缺的部分即下表前两条。审查者按源码推演，没有找到在 Linux CI 上会失败的断言。

| 级别 | 问题 | 处理 |
| --- | --- | --- |
| P2 | 询价阶段的 8 秒时限早于单个请求自己的超时，接口挂起时请求总是被阶段时限中止，而询价器把它当成调用方中止：不记失败、不暂停，每分钟重复 | 已修：`quote` 另收调用方自己的中止信号，只有它中止才不算失败；到了阶段时限的在途请求按超时记失败并暂停该标的 5 分钟；有用例 |
| P2 | 就绪项的计数不含被滤掉的配对：一个配对暂停中或类别不询价、另一个成功时仍判通过 | 已修：`PollStats` 加 `tokenSkipped`（类别没确认写法、暂停中、这一轮中途 token 不可用或到了时限），不为 0 时不按询价判通过，文案与页面写出未询数；有用例 |
| P2 | `openEconomics` 的第四个参数无条件传入，没有询价时成本门槛也取两种口径较大者，比 v0.81.0 严，与文档「不带询价时相同」不符 | 已修：只在样本带询价时传（引擎与回测） |
| P3 | 同一轮里第一个请求被拦截后，队列里其余请求照发 | 已修：每个任务发出前再查 `usable()`，不可用的记未询 |
| P3 | 就绪项去掉了时效判断，公开报价长时间拉不到时仍按很久以前的那一轮判通过 | 已修：只认最近三轮内的上一次拉取；有用例 |
| P3 | 只有应答对不上的原因带标的代码，记录写得比实现宽 | 已修：超时、非 2xx、缺 Python 的原因也带标的代码；记录改准 |

已核实（第二轮）：没有新的凭据泄漏面，错误都是固定文案加过了白名单正则的标的代码；被拒、暂不可用、暂停、失败原因与成功时刻都记在发请求时所用的 token 上；`anySignal([signal], 8 秒)` 符合 L206 的约定，`test/any-signal.test.ts` 的源码扫描不受影响；到时限后没发出的任务不发、这一轮照常出样本；询价器用例里随时钟推进的整串断言、数量与数值解析的新断言、成本门槛三条与就绪项文案的推演都成立。

未能核实（第二轮）：真实接口对写法不对的合约返回什么状态码。如果是 403，会被当作拦截而把整个 token 暂停 5 分钟；上线后先只启用一个配对看询价状态。
