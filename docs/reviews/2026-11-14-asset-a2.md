## 审查结论

两路都无 P0/P1。

后端逐项核实：取锁、核对令牌与 `import-info`、写入、日快照在同一 `BEGIN IMMEDIATE` 事务；TTL / 续期 / 最长持有 / 只删自己令牌与工作台一致，续期定时器不泄漏，异常路径释放锁；导入在锁持有期间提交时写入一律作废；校验与工作台 zod 规则逐条一致（含 zod 3 的 UUID 正则）；`market` 行只改数量、交易所行拒绝；只收 POST，CSRF 覆盖，错误映射不回显 SQL。

页面逐项核实：全页单写者防重、卸载后不 setState、401 转登录；出金与资金流编号在打开表单时生成、重试沿用；资金流修改的字段正好是服务端白名单；hooks 均在早返回前；与工作台的字段、约束、文案一致。

| 级别 | 问题 | 处理 |
| --- | --- | --- |
| P2 | 服务连接 `busy_timeout` 5 秒是同步等待，碰上导入事务会卡住整个服务进程 | 已修：服务连接降到 1 秒，导入连接仍 5 秒；文档写明 |
| P2 | 只读回退接住所有错误，导入占锁导致的 BUSY 也提示“属主不是服务账户” | 已修：只有属主核对失败或 SQLite READONLY/PERM/CANTOPEN 才算只读；BUSY 只读打开但写入报“资产正在更新，请稍后重试”；其他错误照常抛出。用例见 `test/asset-writes.test.ts` |
| 建议 | 只读提示“请重新导入”指错了路（导入遇到属主不对的文件同样拒绝） | 已修：改为提示 chown 并可写 |
| 建议 | 属主核对 `assertOwnFiles` 没有测试 | 已修：补 uid 不符与符号链接两种情形 |
| P2 | 结果未知、409 或成功但应答无法解析时账本没有重读，与文档不符 | 已修：这些情形同时重读账本；已用应答更新的成功路径不重读 |
| P2 | 新增的 `.button:disabled` 规则覆盖了工作台的 `cursor: not-allowed`，工作台也没有 `.icon-button:disabled` | 已修：删掉该规则 |
| 建议 | 资金流表单与编辑面板可同时展开，共用一条报错 | 已修：报错记下发起的接口，只显示在对应面板 |
| 建议 | 残留只读文案（“查看出金记录”“沿用表格估值”）与过时注释 | 已修：照工作台改为“管理出金记录”“沿用表格估值，可手动编辑”，注释更新 |
