# DEX 价差模块（原 Var / Lighter 价差回归）：方案与现状

Var（Variational Omni）与 Lighter 两个场所——Lighter RH（`api.rh.lighter.xyz`）与 Lighter 主网（`mainnet.zklighter.elliot.ai`）——共有标的的价差采集、基线、回测、模拟盘与实盘前准备。**目前只做模拟盘：只读公开行情，不向任何交易所下单。**

**v0.88.0 起推广为通用两腿价差**：场所加上 Entropy（Hyperliquid `io` 市场），按场所组合自动配对，另可手动配对并给乘数；配对键、样本与持仓字段、存储表、采样节拍与页面的变化见 [dexspread.md](dexspread.md) 第 10 节，与本文冲突时以那里为准。本文其余规则（基线、时段、开平仓、风控、失联、询价、回测不看未来）照旧适用，文中的「Var」「Lighter」「卖 Var」在两腿口径下分别读作 A 腿、B 腿、「卖 A」。

## 1 范围（v0.80.0，R2）

- 新模块，只读公开接口，只写自己的 `varlighter.sqlite`；不碰执行器、划转、资金与凭据。按 [code-review.md](code-review.md) 定为 R2。
- 默认开启（与 EQN 快讯一样），`config.json` 写 `"varLighter": false` 关闭；没有需要导入的工作台数据，不进「从工作台导入」。
- 工作台没有对应页面；页面骨架照 Ondo 页，见 [frontend.md](frontend.md)《DEX 价差页》。
- 回滚版本：v0.79.1。回滚后 `varlighter.sqlite` 留在数据目录，不影响其他模块；重新升级接着用。

### 实盘前的策略收紧（v0.81.0）

仍然只做模拟盘，不接下单。按「分级存疑取高」定为 R3：`varlighter.sqlite` 的 `samples` 表加了两列。

- **改变的行为**：全天基线不开仓；开仓前按判断时刻的 Lighter 一档复核并按那一刻的价成交（平仓同样）；预期净利低于 `minNetBps` 不开仓；`maxQuoteAgeSec` 默认 90 → 30 秒；下单预演的限价保护改为滑点预算。细节见第 5、6、8 节。模拟盘开仓会明显变少，结果更接近实盘。
- **影响面**：只有本模块的模拟盘、回测、预演与自己的库；不碰执行器、资金与凭据。已保存的参数不自动改：每次保存都写整份全局参数，所以保存过任何参数（包括启用过标的）的库里 `maxQuoteAgeSec` 仍是 90，要在页面上改成 30。
- **失败与回滚**：回到 v0.80.1。多出的两列可空，旧版本按列名读写，不受影响；新加的全局参数另存在 `globalExtra`，旧版本读 `global` 时不会遇到不认识的字段，已启用的标的与参数照常生效（旧版本下次保存参数时丢掉 `globalExtra`，再升级回来 `minNetBps` 回到默认 3）。
- **本次不做**：两边下单连接器、登录后的 Var 实时询价、分钟内的止损、资金费进盈亏。

### Var token 询价（v0.82.0）

仍然只做模拟盘，不接下单。R3：读已保存的 Var 会话凭据并带着它发请求，放宽了 Var 传输的请求体白名单，`samples` 表加三列。

- **目的**：公开报价每分钟拉一次，收到时已过去几十秒（2026-11-23 实测 50 到 80 秒）。Var 的公开价格流（`wss://omni-ws-server…/prices`，免登录）只有标记价、没有买卖价，还按来源限流，没有采用。登录后的询价接口 `POST /api/quotes/indicative` 按数量给买卖价与报价时刻，行情监控的原油页已在用同一个接口和同一个 token。
- **改变的行为**：数据目录里有可用的 Var token（行情监控「原油」页的 Var token 表单或工作台导入写入的 `monitor-variational-session.json`）时，每分钟拉公开报价的同时，给已启用或有持仓的配对各询一次价，空仓数量按名义金额除以 Var 标记价折算为四位有效数字，持仓按 Var 腿实际单位数询价。样本保存买卖价、应答核对过的数量、交易所报价时刻和本机应答时刻。复核、模拟成交、估值与回测在数量与时效都相符时使用询价。
- **没变的**：信号仍按每分钟的公开报价发现，平仓、止损、超时的判断也仍看公开报价的样本，询价只决定复核与成交价。没有 token、token 过期或被拒、询价失败、询价的报价时刻早于 15 秒、类别没有确认过写法（ETF、贵金属、未上市、其他；只询加密货币、股票、商品）时，该样本不带询价，开平仓规则与 v0.81.0 相同。有可用 token 时每轮多一个询价阶段（总时限 8 秒），样本可能比 v0.81.0 晚建至多这么久。样本带询价时，成本门槛（往返成本不低于止损线不开仓）取按询价复核后与报价时刻两种口径里较大的往返成本，因为止损仍按公开报价判断；不带询价时不变。本模块不写、不验证、不保存 token，也不调 `/api/me`。
- **影响面**：
  - 凭据：本模块新增对 `monitor-variational-session.json` 的只读访问（每次用时重读，权限不是 600 的文件照旧忽略）。token 只经传输脚本的标准输入发往 `omni.variational.io/api/quotes/indicative`，不进日志、接口应答与页面；状态视图只有状态、到期时间、最近成功时刻、延迟与固定文案的错误。
  - 传输白名单（`src/monitor/variational-transport.ts` 与 `scripts/variational-request.py` 两处同样的检查）：询价请求体原先只允许 BZ、CL 的商品合约且数量为 `1`；现在允许三种逐字段重建的合约写法（`perpetual_rwa_future` + `kind` 为 `commodity` 或 `equity`；`perpetual_future` + `funding_interval_s` 为 3600），标的为 1 到 16 位大写字母数字，数量为正的十进制文本（整数至多 12 位、小数至多 8 位）。主机、路径、方法、请求头不变，仍是只读的询价；行情监控的原油读取不受影响。
  - 进程：每个询价起一个 `python3` 子进程（同行情监控），同时最多 4 个，每分钟最多 20 个（每个场所至多 10 个取快照的配对），整个询价阶段 8 秒内结束（到点后没发出的不再发、在途的中止并按超时记失败）。这一轮里有请求被拒或被拦截后，剩下的也不再发。服务器没有 `python3` 或被 Cloudflare 拦截时询价状态为「暂不可用」，其余照常。退避：被拦截后这个 token 停 5 分钟；单个标的失败（超时、非 2xx、应答对不上）后该标的停 5 分钟，写法不对的合约每 5 分钟才重试一次。
  - 同一个 token 被行情监控与本模块同时使用。被 Var 拒绝（401 且 `x-omni-auth: r`）后本模块不再用这个 token 发请求，直到文件换成新的；行情监控一侧各自判断。
  - 数据库：`samples` 加三列可空列 `var_bid_tk`、`var_ask_tk`、`var_tk_at`，启动时 `ALTER TABLE` 补上。
- **失败与回滚**：回到 v0.81.0。多出的三列旧版本按列名读写，不受影响；token 文件本模块没有动过；白名单随代码一起回到原样。只想停询价而不回退时，在行情监控的 Var token 表单里清除 token（原油页随之退回公开价格）。
- **待实测**：询价接口对股票与加密货币合约是否接受上面的写法。三种写法是在公开价格流上试出来的，询价接口只有商品（原油）在真实账户上核实过。写法不对时应答不是 2xx 或内容对不上，该配对不带询价，实盘准备页「采集状态」的「Var token 询价」一行显示原因与本轮成功、失败数。
- **本次不做**：分钟内的更快轮询与按询价发现信号、询价应答里 `qty_limits` 的核对、Var 下单。

代码：`src/varlighter/`（模型、行情、Var 询价 `varquote.ts`、统计、策略、回测、库、下单预演、视图类型、引擎）、`src/dex/`（v0.90.0 起的独立服务 `trading-platform-dex`：`host.ts` 打开库与路由，`main.ts` 入口，见 [dexspread.md](dexspread.md) 第 11 节）、`src/service/dex.ts` 与 `src/http.ts`（执行面把 `/api/varlighter/*` 转发给它）、`web/src/varlighter/`（页面）、`scripts/dev-varlighter.ts`（替身行情的本地预览）。测试：`test/varlighter.test.ts`、`web/test/varlighter-form.test.mjs`。

## 2 标的配对、规格核对与时段（`model.ts`）

- **配对键**：`场所:代码`，如 `rh:AAPL`、`lighter:BTC`。同一代码在两个场所是两个配对，各自采样、各自基线、各自参数。样本、持仓、成交、参数、规格确认、回测与接口里的 `symbol` 字段都存配对键；页面上拆成「代码 + 场所」显示。
- **共同标的**：Var `listings` 的 `ticker` 与 Lighter `orderBookDetails` 里 `market_type=perp`、`status=active` 的 `symbol` 相同即配对（主网响应里的 `spot_order_book_details` 不用）。
- **规格核对**（`identity`）：
  - `verified`：在 `KNOWN_KINDS` 清单里、两边标记价相差 ≤ 5%。
  - `review`：同名但不在清单（新上市、小市值、可能重名），两边价差 ≤ 5%。须在实盘准备页按配对人工确认后才能启用模拟盘。
  - `mismatch`：两边标记价相差 > 5%（同名不同物或报价单位不同，例如 OPENAI 约 7.3 倍、主网 US500），只采集不对齐、不能启用。
- **资产类别**决定时段：美股 / ETF 分 `rth`（纽约 9:30–16:00）、`ext`（4:00–9:30、16:00–20:00）、`overnight`、`weekend`（周五 20:00 到周日 20:00）；贵金属与大宗商品（NATGAS）分 `weekday` / `weekend`（周五 17:00 到周日 18:00）；加密货币不分时段（`all`）。节假日按工作日算（见第 12 节）。
- 2026-11-22 实测：Var 593 个标的；RH 72 个永续，与 Var 共有 57 个（已核对 51、待确认 ANT / CASHCAT / PONS / SPCX / USELESS、规格不同 OPENAI）；主网 210 个永续，与 Var 共有 155 个（其中 105 个 RH 没有；规格不同 OPENAI、US500）。两边手续费都是 0。

## 3 数据来源（`feeds.ts`）

| 来源 | 接口 | 频率 | 用途 |
| --- | --- | --- | --- |
| Var 公开报价 | `omni-client-api.prod.ap-northeast-1.variational.io/metadata/stats` | 每 60 秒 | 标记价、资金费、`quotes`（base / 1k / 100k 三档买卖价与 `updated_at`） |
| Var token 询价（v0.82.0，有可用 token 时） | `omni.variational.io/api/quotes/indicative`，经 `scripts/variational-request.py` | 每 60 秒（与公开报价同一轮） | 已启用配对的开仓数量或持仓实际数量、相应买卖价与报价时刻 |
| Lighter 目录 | 各场所 `/api/v1/orderBookDetails` | 每 10 分钟 | 市场编号、精度、最小数量与金额、标记价 |
| Lighter 行情流 | 各场所 `wss://…/stream?readonly=true` 订阅 `market_stats/all` | 实时 | 全市场一档买卖价、标记价、资金费；按时刻保留历史以便回看 |
| Lighter 盘口（v0.89.0 起） | 同一行情流再订阅 `order_book/{市场编号}`（快照加增量） | 实时 | 只订已启用或有持仓的配对，每个场所最多 10 个；v0.88.0 及以前是每分钟一次 REST `orderBookOrders` 快照，见 [dexspread.md](dexspread.md) 第 10.10 节 |

- **Var token 询价**（`varquote.ts`）：合约写法按类别：加密货币 `{ underlying, instrument_type: 'perpetual_future', settlement_asset: 'USDC', funding_interval_s: 3600 }`，股票与商品 `{ underlying, instrument_type: 'perpetual_rwa_future', settlement_asset: 'USDC', kind: 'equity' | 'commodity' }`（公开目录里的 `funding_interval_s` 是 28800，价格流不接受）。应答要求标的与数量对得上请求、买卖价不倒挂、报价时刻在 [现在 − 15 秒, 现在 + 2 秒] 内，否则不用。询价阶段整个限 8 秒，到点用已拿到的。失败原因分缺 `python3`、超时、被拦截、应答对不上等固定文案（被拒与被拦截之外的都带标的代码），在状态里保留 90 秒，同一轮里别的配对成功不会盖掉它。token 的状态分未配置、已过期（到期前 30 秒起）、正常、会话已失效（被 Var 拒绝）、暂不可用（网络、拦截或缺 `python3`）；被拒的判定只落在发请求时用的那个 token 上，请求途中文件换了新 token 不会把新的标成失效。
- **对齐**：Var 报价自带 `updated_at`，收到时一般已过去约 20 秒。每个样本按 Var 报价时刻 `t` 取该场所行情流在 `t` 之前最近的一档；行情流断线后的时刻不算有数据。同一报价时刻不重复计入。
- **盘口冲击**：主网单个市场的 `order_book` 订阅约 550 MB/天，所以只订已启用或有持仓的配对的腿（每个场所最多 10 个）。从当前盘口算出 1k / 100k 美元的成交均价相对最优价的冲击，再把冲击套到对齐时刻的一档价上（`depthAt`）；快照与报价时刻相差超过 120 秒不用。v0.88.0 及以前是每分钟一次 REST 快照（逐笔挂单约 22 KB），v0.89.0 起改为行情流订阅（[dexspread.md](dexspread.md) 第 10.10 节）。冲击变化比一档价慢得多，这是近似，见第 12 节。没有快照的配对用一档价估算 1k 档（页面标「估」），100k 档不可算。
- **流量**（2026-11-22 实测，线上 permessage-deflate 压缩后）：RH `market_stats/all` 约 245 MB/天（解码后 1.09 GB），主网约 510 MB/天（解码后 2.4 GB）。页面「采集状态」按解码字节数折算每天的量。实盘准备页可以按场所停采，至少保留一个场所；停采前须先停用该场所上的标的并平掉模拟持仓（接口返回 `venue_busy`）。
- 行情流 60 秒重订阅一次以刷新快照；20 秒没有任何消息、或发起连接 20 秒还没连上就重连，按 1、2、4… 秒退避、封顶 60 秒，收到快照后退避清零；状态里有连接时长、最后消息、重连次数与最近错误。
- 请求响应按字节流式限长（`vendor/response.mjs`），超限即中止。停服时后台循环中断进行中的目录、报价与快照请求，不等 20 秒超时。

## 4 基线与统计（`stats.ts`）

- 中间价基差 = Var 中间价 ÷ Lighter 中间价 − 1（基点）。基线是该配对、该时段在最近 `windowHours`（默认 24 小时）窗口内基差的中位数，离散度用 MAD×1.4826（σ）。该时段样本不足 `minSamples`（默认 120）时退回全天窗口（页面标「全天基线」），仍不足则不判断。全天基线只用于展示和已有持仓的平仓判断，不开仓：窗口 24 小时，时段刚切换（周一开盘、周五 20:00 进周末、贵金属周末前后）的头两小时全天窗口里是上一个时段的基差。
- 可成交价差：卖 Var 价差 = Var 买价 ÷ Lighter 卖价 − 1，买 Var 价差 = Var 卖价 ÷ Lighter 买价 − 1（都除以 Lighter 中间价），按名义金额取档（≤ 1000 美元用 1k 档，否则 100k 档）。持仓的平仓与止损按实际数量取价：市值在开仓名义金额 ±20% 以内沿用名义金额的档位，超出才按市值取档（v0.100.1，见 [dexspread.md](dexspread.md) 第 10.13 节）。
- 详情页按时段给出分布（中位数、均值、σ、5% / 25% / 75% / 95%）、1k 档往返成本中位数、AR(1) 半衰期、每天穿越中位数次数、达到入场偏离的样本占比，并按统计给出建议入场偏离。

## 5 策略与模拟盘（`strategy.ts`、`engine.ts`）

- **开仓**：卖 Var 价差 − 基线 ≥ 入场偏离 → 卖 Var、买 Lighter（`var_rich`）；基线 − 买 Var 价差 ≥ 入场偏离 → 买 Var、卖 Lighter（`var_cheap`）。按可成交价差判断，已含半个往返成本。
- **开仓复核**（`confirmOpen`）先用对齐样本发现信号。询价、读取盘口、预热基线并取得账户风控输入后，逐配对记下最终决策时刻 `decisionAt`。行情流腿用判断时刻的一档平移已知深度冲击，Var 腿取匹配数量的有效询价或适用公共档。逐腿将最终采用的来源时刻与 `decisionAt` 比较，任一腿超过 `maxQuoteAgeSec` 就记「报价过旧」，等于上限仍可用。缺判断时刻一档、缺时间证据和信号已消失分别计数。基线或账户风控暂时读不到时，已采到的行情照常落库并计入统计，决策时刻留空，模拟盘和回测均跳过该次开仓。
- **Var 成交数量**。新仓使用询价时，按 Var 应答确认的数量成交，按配对乘数对冲。持仓与询价按相同的原生合约单位匹配；Var 在 B 侧时，数量等于持仓的 A 数量乘以乘数。旧样本无数量、当前参数与询价不匹配、或旧仓数量超出询价接口八位小数精度时，按公共档位取价。成交记录的 `entryVarSource`、`exitVarSource` 给出 `token`、`1k`、`100k` 或 `0`（公共一档）。
- **平仓**：中间价基差回到距基线 `exitBps` 以内（回归）；按可成交价的浮亏达到 `stopBps`（止损）；持有超过 `maxHoldMinutes`（超时）；手动平仓。平仓判定用中间价，否则中间价回到基线时可成交价差仍差半个往返成本，永远等不到平仓。
- 持仓按每腿实际数量与当前价格选公共档。自动、手动、失联平仓、浮盈和回测期末估值使用同一规则。缺少大档的腿可降档，能用原档的另一腿保留原档。缺判断盘口、降档或超过 100k 公共档容量时标为估算。总览与失联持仓的浮盈沿用模拟盘标记，开仓价或本次估值采用估算价时都显示「估算」。
- 冷却写进 `state` 表，重启后仍生效。
- **报价复核后的开仓风控**：暂停、未启用、规格未确认、时段不允许、本时段基线样本不足（全天基线）、冷却中、往返成本已达止损线、预期净利不足（`minNetBps`，默认 3 基点）、**同一 Var 代码已在另一场所持仓**、持仓数已满、名义合计超上限、当日（UTC）亏损已达上限。同一 Var 代码在 Var 上是一个净持仓，两个场所同时开仓会互相抵消，所以按代码互斥；两个场所同时有信号时按配对顺序（RH 在前）开一笔。
- **预期净利**（`expectedNetBps`）= 偏离 − 出场偏离 − 半个往返成本（开仓时的）− 四次成交的滑点 − 两边开平的手续费。往返成本高的标的偏离刚到入场线时不开。另有一道单独的门槛：开仓时的往返成本（买 Var 价差 − 卖 Var 价差）不低于 `stopBps` 时不开，因为开仓后按可成交价的浮亏一开始就等于往返成本，下一个样本就会止损；这一条与偏离多大无关。
- **盈亏**：两腿按开平仓时的可成交价结算，滑点与手续费按四次成交的名义金额扣（默认滑点 1 基点、两边手续费 0）。资金费按持有时长估算，只作参考，不进净盈亏。
- 默认参数：每笔 1000 美元、入场 15 基点、出场 0、止损 60、最长持有 720 分钟、冷却 10 分钟；最多 5 笔、名义合计 10000 美元、当日亏损 100 美元。参数带版本号，保存时版本不一致返回 409。
- **自动配置**（v0.93.0）：配对键在 `settings.auto` 里时，入场、出场、止损、最长持有四项不用保存的值，改用推荐值（`recommendParams`）；名义金额、冷却、时段、方向仍用保存的值。保存的四项不动，关掉自动配置即回到它们。推荐值按该配对最近 `min(基线窗口, 72)` 小时的样本统计（与详情页「分时段统计」同一个 `symbolStats`），每 10 分钟重算一次；当前时段的样本数达到 `minSamples` 用该时段，否则用全天。算法：
  - 入场 = max(5, 四舍五入(偏离 95 分位 − 往返成本中位数 ÷ 2), 向上取整(保本线))，上限 2000。保本线 = 往返成本中位数 ÷ 2 + 4 × 滑点 + 2 ×（A 手续费 + B 手续费）+ `minNetBps`，即出场为 0 时刚到入场线的预期净利不低于最低净利。滑点、手续费与 `minNetBps` 取当前全局参数，改了马上生效，不等 10 分钟。
  - 出场 = 0。止损 = 四舍五入(往返成本中位数 + 3 × 入场)，限在 20 到 5000。最长持有 = 向上取整(6 × 半衰期)，限在 60 到 1440 分钟；统计不出半衰期时 720 分钟。
  - 100k 档整个窗口都没有成本时按 1k 档算成本。样本数不够、或没有可成交价算不出往返成本时没有推荐值：不开仓（原因「自动配置的样本不足」，排在规格未确认之后），读数与已有持仓的平仓按保存的参数。
  - 两腿都是行情流的配对几秒一个样本，算推荐值前先按约一分钟取一个（与基线同一间隔），样本数门槛与半衰期和含 Var 的配对同口径。
  - 自动配置下开的仓把开仓时的出场、止损与最长持有记在 `state` 表的 `autoExits` 里（按配对键，带持仓编号），之后一直按这三项平仓；推荐值随时段切换或重算变了、关掉自动配置，都不动已有的仓。平仓或清空模拟盘时删掉。开仓事件注明「（自动配置）」与当时的入场线。回测不受影响，仍按表单参数。
- 模拟成交未计入排队、两腿之间的延迟与部分成交。

## 6 回测（`backtest.ts`）

- 用已采集的对齐样本按时间重放，与模拟盘同一套基线、开平仓与风控（不含跨标的的持仓数、名义合计与当日亏损）。基线在每个样本判断之后才计入该样本，不看未来；起点之前的样本只用来预热基线。
- 复核规则由每行采样证据决定。新样本的 `captureKind=decision`，缺任一行情流判断盘口或时间证据就拒绝开仓。首次打开确实从未加过判断盘口列的旧库时，已有行登记为 `aligned`，按对齐公共价和当年仅保存的接收时刻回放，成交标为估算。其余旧行和缓存的来源未知，照常预热基线，达到入场条件时记入缺证拦截。汇总分别给出旧口径样本、其估算开仓数和缺决策时刻样本数。窗口内首条正常盘口的位置不参与判定。
- 时长 1–336 小时；返回汇总、累计净盈亏曲线、最多 1000 笔成交、按原因统计的「达到入场但没开仓」。期末持仓按最后一个样本估值。

## 7 存储（`store.ts`）

- `varlighter.sqlite`（v0.89.0 及以前在执行面数据目录下；v0.90.0 起在 DEX 价差服务的 `/var/lib/trading-platform-dex`，见 [dexspread.md](dexspread.md) 11.5），表：`samples`（配对键 + 报价时刻为主键）、`paper_positions`、`paper_trades`、`events`、`state`（参数、冷却）。样本另有按报价时刻的索引。v0.81.0 起 `samples` 多两列 `rh_bid_rx`、`rh_ask_rx`（判断时刻的 Lighter 一档，可空），打开库时用 `ALTER TABLE … ADD COLUMN` 补上，旧样本为空。参数存在 `state` 的 `settings` 里；v0.81.0 新加的全局参数另放在 `globalExtra`，原因见第 11 节。样本保留 14 天，每小时按时刻分批（每批 2000 条、批间让出事件循环）清理；事件保留 30 天；成交不清理。
- v0.82.0 起 `samples` 另有 `var_bid_tk`、`var_ask_tk`、`var_tk_at`（判断时刻的 Var token 询价与 Var 给的报价时刻，可空）；没有询价的样本为空。
- 容量（2026-11-22 用合成数据实测）：两个场所约 210 个配对，每天约 30 万条样本，14 天约 420 万条、库文件约 0.85 GB，数据目录需留出 1 GB 以上；每分钟写入一批约 16 ms。总览的「24h 样本」按主键逐配对计数（满量约 60 ms），10 分钟内只数一次、其间随写入累加，因此最多晚 10 分钟扣掉过期的样本。
- v0.93.0 起两腿都是行情流的配对采样加快（未启用 20 秒、已启用或有持仓 5 秒，见 [dexspread.md](dexspread.md) 第 10.11 节），容量按配对数重估：每个这类配对未启用时每天 4320 条、启用后 17280 条。按每条约 200 字节（上面实测的 0.85 GB ÷ 420 万条）折算，例如 210 个含 Var 的配对加 30 个行情流配对、其中 10 个启用，每天约 56 万条，14 天约 790 万条、约 1.6 GB，DEX 状态目录建议留出 2.5 GB。这是折算，没有用合成数据重测。
- 清空模拟盘（输入 RESET）只删持仓、成交与冷却，参数、规格确认、自动配置的选择与样本保留。
- 数据库提交后，页面才会看到开仓、平仓、冷却、参数版本或重置结果。平仓的成交、持仓删除、冷却和事件共用一个事务；保存参数与对应事件、重置模拟盘与对应事件也分别一同提交。写入失败时保留上一份状态，重试会从同一份持仓和冷却继续。

## 8 下单预演与实盘准备（`plan.ts`、`engine.ts` 的 `readiness`）

- 详情页按最新样本与当前名义金额给出两个方向的计划：两腿数量（按 Lighter 精度向下取整）、预期价、带滑点保护的限价（每条腿每次成交的保护 =「入场 − 出场 − 半个往返成本 − 手续费 − `minNetBps`」÷ 4，限在 1 到 10 基点：偏离刚到入场线时四次成交把保护用满仍剩最低净利；算出来不足 1 时取 1，这时用满会低于最低净利。原先取 `max(10, 入场偏离)`，两腿合计可让出的滑点超过整笔利润。预期价与限价仍以报价时刻的样本为基准，没有换成判断时刻的一档，时效核对也仍是固定的 90 秒），核对 Lighter 最小数量、最小金额、精度，以及 Var 报价不超过 90 秒、对手一档与 Var 报价时刻相差不超过 75 秒；顺序：Var 先按询价成交 → 按 Var 实际成交数量在对手场所下 IOC 限价单 → 未成交部分在 Var 反向平掉、记单腿事件、连续两次单腿暂停该标的 → 平仓顺序相同、Lighter 用 reduce_only。只生成计划，不签名、不发送。
- **实盘的行情口径（v0.93.0 之后登记的要求，尚未实现）**：实盘的开仓、平仓与止损判断由行情流的推送触发，按推送到的最新一档与盘口判断和下单。模拟盘用的固定间隔样本（行情流配对 5 秒 / 20 秒，含 Var 腿的每分钟）和每分钟拉一次的 Var 公开三档报价（base / 1k / 100k，收到时已过去几十秒）不作为实盘的成交依据，只继续用于基线、回测与模拟盘统计。Lighter RH、主网与 Entropy 的腿已有行情流（一档，以及已订阅市场的盘口），接实盘时改成每次推送就判断（模拟盘 v0.94.0 起已对两腿都是行情流的配对这样做，见 [dexspread.md](dexspread.md) 第 10.12 节）。Var 没有带买卖价的公开推送（公开价格流只有标记价，还按来源限流）：Var 腿由对手腿的推送或 Var 标记价的推送触发，下单前按实际数量即时询价（token 询价），以询到的价为准；登录后是否有带买卖价的推送待实测，有就优先接入。
- 实盘前核对：采集（Var 与所有采集中的场所）、基线至少 3 天、选定标的、规格核对、盘口快照（3 分钟内）、模拟盘至少 20 笔且净盈利、Var 报价时效（< 45 秒）、风控限额；以及四项「待接入」：Lighter 下单连接器（RH 与主网是两套账户，各需 API 密钥与签名器）、Var 下单接口、两边账户资金、实盘监控与告警。「待接入」在模拟盘阶段不会变成已就绪。v0.101.0 起多一项「场所账户」，「账户资金」按 `install.sh --set-dex-keys` 录入的账户实际读到的可用余额判断（Lighter 主网、Lighter RH、Entropy；Var 不在内），不再固定为待接入；下单连接器等三项仍是待接入。见 [dexspread.md](dexspread.md) 第 12.13 节。

## 9a 交给 AI 分析与优化（v0.83.0）

只读令牌可以读本模块的 GET 接口（`state`、`symbol`、`paper`、`readiness`、`samples`），POST（回测、参数、平仓、清空）一律不行，做法见 [mcp.md](mcp.md) 第 8.3 节。

在仓库目录里打开 Claude Code，按 [mcp.md](mcp.md) 第 4 节接上只读 MCP，就有两个工具：

- `varlighter`：读总览、单个配对、模拟盘与实盘准备。
- `varlighter_backtest`：先把该配对的样本增量拉到本机（默认 `~/.cache/trading-platform/varlighter`，`TP_VARLIGHTER_DIR` 可改），再在新进程里用仓库当前的 `backtest.ts` 重放。`params`、`global` 覆盖已保存的参数，`grid` 扫参数（最多 200 个组合，按净盈亏排序）。

不经 MCP 时同样可以在命令行做（环境变量同 MCP）：

```bash
node tools/varlighter/pull.ts --enabled                     # 拉已启用、有持仓和失联配对的样本
node tools/varlighter/backtest.ts --symbol rh:AAPL --hours 168 --params '{"entryBps":25}'
node tools/varlighter/backtest.ts --symbol rh:AAPL --grid '{"entryBps":[15,20,25,30],"exitBps":[-5,0,5]}'
```

本机样本从上次的最后一条接着拉，所以可以积累超过服务器 14 天保留期的历史；回测时长 `--hours` 以本机样本为准，省略时回放全部（扣除第一个基线窗口）。回测输出的 `gaps` 列出本机样本里超过 30 分钟的空档（停服或拉取间隔超过保留期），分析时注意这些时段没有数据；`skipped` 不为 0 说明本机文件里有重复或乱序的行，删掉该配对的 `.jsonl` 重新拉取即可。

用法：先让 AI 看总览与模拟盘，找出赚钱和亏钱的配对与平仓原因；再用 `grid` 扫入场、出场、止损、最低净利等参数；要改策略逻辑时改 `strategy.ts`、`stats.ts` 等，再用同一批样本对比改动前后。回测结果不会改平台上的参数：参数要在页面上保存，代码改动照常审查、发布。回测与模拟盘同规则，但仍有第 12 节的局限（例如盘口冲击为近似、止损按公开报价判断），回测赚钱不等于实盘赚钱。

## 10 页面（`#/varlighter`）

四个页签：价差总览、标的详情（`#/varlighter/detail/<配对键>`）、模拟盘、实盘准备。页头每个场所一枚状态（行情流、配对数、盘口快照新鲜度）；总览可按场所筛选，同一代码的两行带场所标签。总览上方列出「失联的标的」：已启用或有模拟持仓、但已失联的配对键，可停用，持仓按最后一个样本平仓并在事件里注明原因；没有新样本时这些持仓不会自动止损或超时。失联指三种情况：不在目录里（下架）、两边价格相差超过 5% 改判为规格不同、数据源都正常而 30 分钟没有新样本（Var 无报价或对手盘口缺失）。Var 拉取失败超过 3 分钟、场所目录未取到、行情流断开、连上后还没收到快照或启动后还没拉到 Var 时属于整体故障，一律不判失联，手动平仓也要等恢复。30 分钟从最后样本与数据源连续正常的起点（启动、Var 恢复、行情流收到快照）中较晚者算起，停机前的旧样本不会在恢复后立刻被判失联；Var 中断不超过 3 分钟再恢复的不重新计时，行情流同样处理（v0.80.1 起），否则频繁的短暂断线会让没有报价的持仓一直处理不了。非加密标的在周末、夜盘时段的原因里注明「可能休市」。实盘准备页的「采集状态」按场所给出行情流、流量、目录与盘口快照，并有停采 / 开采开关；规格核对按配对确认。v0.88.0 起场所停采 / 开采开关换成「自动配对」的组合开关与「手动配对」管理，见 [dexspread.md](dexspread.md) 第 10.4 节。布局与验收见 [frontend.md](frontend.md)《DEX 价差页》。v0.92.0 起总览表格默认是 6 列的简洁视图（当前价差、距开仓、操作方向、交易成本），可切回原来的完整视图。

v0.93.0 起总览表格的「模拟盘」列排在标的后面，带复选框：勾选即启用该配对并交给自动配置（第 5 节），取消勾选只停用；规格待确认或不同的配对不能勾选。详情页「参数与回测」顶部有自动配置的开关、当前推荐值与依据（时段、样本数、更新时间）以及「填入表单」按钮；自动配置开着时四个输入框下注明当前生效值，输入框里仍是保存的值。

实盘准备页「采集状态」在 Var 公开报价下面有一行「Var token 询价」（v0.82.0）：状态、最近成功时刻与收到时距 Var 报价时刻的延迟、上一轮成功与失败数、token 到期时间、最近一次失败的原因；不是「正常」时提示去行情监控的原油页保存 token。「实盘前核对」的「Var 报价时效」在最近三轮内的上一次拉取里已启用或有持仓的配对全部询到时按询价的延迟判断；有失败或未询的（类别没确认写法、暂停中、到了时限）时写出成功、失败、未询各几个，仍按公开报价的时效判断。旧服务端没有这一项时整行不显示。

## 11 回退

从 v0.94.0 回到 v0.93.0：不改库表与参数，两腿都是行情流的配对开平仓回到按 5 秒样本判断。

从 v0.93.0 回到 v0.92.1：参数记录顶层多出的 `auto` 旧版本不读也不报错（没有放进 `symbols` 的参数里，旧版本读到参数里不认识的字段会整份重置）。回退后用自动配置的配对按保存的参数继续运行、仍是启用状态；总览勾选启用而没改过参数的，保存的就是默认值（入场 15、止损 60）。自动配置下开的仓在旧版本里也按保存的参数平仓（`autoExits` 旧版本不读）。旧版本保存参数时会丢掉 `auto`，再升级后要重新勾选。样本表不变，采样回到 15 秒 / 每分钟。

从 v0.88.0 回到 v0.87.0：旧版本只读旧表（`samples`、`paper_positions`、`paper_trades`）与旧参数键，看到的是升级那一刻的模拟持仓、成交和参数；升级后的新样本、新成交、手动配对与参数改动看不到，`samples` 从升级起是空档。只是模拟盘，可接受；回滚后建议在页面清空模拟盘。再升级时不重复迁移（`legs_migrated` 标记），回滚期间旧版本写进旧表的样本照常合并读到，但回滚期间的模拟持仓、成交与参数改动不再迁过来。迁移失败时整体回滚，模块在那次运行里不可用（接口 503），下次启动重试。详见 [dexspread.md](dexspread.md) 第 3.3、10.3 节。

回到 v0.79.1：页面与接口消失，`varlighter.sqlite` 保留；或保持版本、`config.json` 写 `"varLighter": false` 只停这个模块。

从 v0.82.0 回到 v0.81.0：`samples` 多出的三列可空，v0.81.0 按列名读写，照常工作；不需要清理任何文件。

从 v0.81.0 回到 v0.80.x：`samples` 多出的两列可空，v0.80.x 读写都按列名，照常工作。v0.80.x 读参数时遇到 `global` 里不认识的字段会整份改用默认值（所有标的变成未启用），所以 v0.81.0 新加的 `minNetBps` 不写进 `global`，另存在同一条记录的 `globalExtra` 里；以后再加全局参数也放这里。读 `globalExtra` 时只取本版本认识的键，值不合法就用默认值，多出的键忽略：更新的版本往里加了字段再回退，不会让整份参数退回默认。

## 12 已知限制

- 模拟成交仍偏乐观：Lighter 一侧按判断时刻的一档；Var 一侧有 token 询价时按询价（是参考价，不是成交回报），没有时仍是几十秒前的公开报价；不计排队、两腿之间的延迟与部分成交。
- Var token 询价（v0.82.0）：股票与加密货币合约的写法待服务器实测；应答里的 `qty_limits`（最小数量、步长、上限）没有核对；token 会过期，要在行情监控的原油页重新保存；信号发现与平仓判断仍按每分钟的公开报价，询价只在这一轮里取一次；询价只有该采样中请求的一个数量，回测改名义金额时可能改用对应的公共档。止损与超时仍按公开报价的样本判断，页面浮盈按询价，两者可能对不上。询价状态（正常 / 暂不可用）是整个 token 一份，一轮里有成有败时以最后结束的请求为准，要看「上次：成功、失败」的计数与保留的原因。同一代码在两个场所都启用时会各询一次。下单预演（`plan.ts`）仍用公开报价的样本。
- 时段刚切换的头两小时（本时段样本攒够 `minSamples` 之前）不开仓；`maxQuoteAgeSec` 默认 30 秒，任一腿实际采用的价格在决策时超过它就只采集不开仓，线上要看有多少样本被挡（实盘准备页的上次拉取里有计数）。
- 判断时刻的一档要求行情流最近 5 秒内有消息。场所在休市时段消息稀疏时会取不到，那一轮不开仓、平仓退回样本本身的价。线上占比待实测：按场所和时段看 `samples` 里 `rh_bid_rx IS NULL` 的比例。
- 含 Var 腿的配对，止损、超时只在样本时刻（每分钟）判断，两次样本之间的极端行情看不到。两腿都是行情流的配对 v0.94.0 起一档变化即判断入场、出场、止损与最长持有（[dexspread.md](dexspread.md) 第 10.12 节）；按推送判断而没有成交的时刻不留样本，回测看不到，换参数回测时模拟盘的成绩可能好于回测；启用很多个这类配对时的 CPU 占用未实测。
- 自动配置（v0.93.0）：推荐值是按近期统计的经验公式，没有按回测结果择优，也不保证盈利；统计窗口最多 72 小时，行情结构变了要过一段时间才跟上。时段切换时推荐值会马上换成另一个时段的统计（只影响之后新开的仓）。样本不足时不开仓，新上的配对要先采够 `minSamples` 个样本（默认 120 个，按约一分钟一个算约两小时）。每个自动配置的配对每 10 分钟同步读一次窗口内的样本并重算，启用很多个 5 秒采样的配对时可能短暂占住事件循环，未实测。总览里勾选总是打开自动配置，想用手动参数要到详情页关掉。
- 盘口快照的冲击套到一档价上是近似：一分钟内深度变化大时 1k / 100k 档不准；没启用的配对 1k 档按一档估算。
- 时段不认节假日（美股休市日按工作日算），港股等非美股标的（如 TENCENT）没有单独时段，归入「其他」按美股时段切分。
- 资金费只估算、不进净盈亏；Var 年化费率的口径是推测。
- 参数用版本号防覆盖，没有逐请求的幂等键。
