# 海力士两腿名义平衡与单腿调平 H2（R3）审查记录

- 日期：2026-11-16
- 范围：`src/contracts.ts`（调平意图）、`src/executor.ts`（单腿调平任务的预览、确认加锁、发送前检查、推进、结算与任务视图）、`src/hynix/{balance,balance-store,balance-alert,market}.ts`、`src/service/{oil,main,feishu}.ts`、`src/http.ts`（`POST /api/hynix/balance/settings`）、页面 `web/src/{HynixPage,HynixBalance,OilPage}.tsx`、`web/src/{hynix-balance,oil-types}.ts`、`scripts/dev-hynix.ts`、对应测试与文档、`package.json`（版本号）。
- 起因：用户要求把“持仓过程中两腿名义金额保持相等”做进海力士交易：净敞口读数、页面可改的阈值、飞书告警、一键调平。自动调平用户决定不做。
- 等级：R3（新增单腿下单任务，改执行状态机）。独立只读审查三路，审查者与作者上下文隔离：后端 R3 审查（高风险档）、后端安全审查（鉴权、凭据与交易执行边界）、页面 R3 审查。
- 回滚：`sudo bash install.sh --version v0.51.0`（提交前 main 上先发布了 v0.51.0 页面在线更新，本批变基其上，版本号顺延为 v0.52.0；v0.51.0 与 v0.50.0 读取任务的代码相同），不用改配置，`hynix.sqlite` 旧版本不读。只有还没做过调平任务时才能干净回退，见下“回滚的实际影响”。

## 变更前对齐

- 用户可见行为、口径、调平任务规则、读数与告警、影响面、本次不做：[docs/hynix.md](../hynix.md) 第 7 节（动手前写好，做完回填）。
- 回滚的实际影响：旧版本按双腿读取任务。库里只要有调平任务（含已完成、已失败的），旧版本读到它就出错：有未结束或待人工处理的调平任务时，旧版本启动时检查未结束任务（`strandedOilJobs`）抛错，整个服务起不来，所以回退前必须先在本版本把调平任务处理到结束；已结束的只要还在最近 20 个任务里，主页 `/api/state` 读不出，在最近 20 个海力士任务里时 `/api/hynix/state` 也读不出，直到被 20 个更新的任务挤出去（任务记录不清理）。做过调平任务之后出问题，应升到修复版本而不是回退。不点调平按钮不会产生这类任务；读数、设置与告警对回退没有影响。本次没有做让旧版本可读的数据迁移，按“写清并接受”处理（README 回退表、hynix.md 7.5）。
