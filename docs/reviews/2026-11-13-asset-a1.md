# 资产模块第一批只读账本（R2）审查记录

- 日期：2026-11-13
- 范围：见 [docs/asset.md](../asset.md) 的 A-1。`src/asset/*`（口径文件复制自工作台 `modules/asset`）、导入命令 `src/asset/import.ts`、`/api/asset/*` 只读接口、`web/src/AssetPage.tsx` / `AssetTrend.tsx` / `asset.css`、`scripts/asset-demo.ts`。
- 等级：R2（独立库 `asset.sqlite`，只读来源账本，不导入凭据，不碰主库与执行器）。因涉及凭据边界，一路独立审查按高风险档进行（只读，与作者隔离）。
- 回滚：从 `config.json` 删掉 `asset`，或 `sudo bash install.sh --version v0.10.0`（回退前同样要删 `asset`）；`asset.sqlite` 可以留着或删掉。

## 审查结论

无 P0/P1。逐项核实无误：
- 工作台的 `connections`（加密凭据）表从不读取；`-status` 与 `aster-accounts` 按白名单取字段。
- 来源库只读打开；全部读出并校验后才打开目标库；三张表在一个事务里整体替换，出错回滚。
- 接口都要登录、只有 GET；`period` 的编号两处校验；没配 `asset` 时 404；库打不开不影响服务启动。
- 口径文件与工作台当前文件逐个对比，只差文件头注释、import 后缀和去掉的 `owner` 条件；搬来的用例期望值没有改。
- `asset.css` 的选择器都在 `.asset-desk` 下；页面没有内联样式；时间按北京时间。
- 快照里的 `generation` 是对随机 IV 密文的摘要，不能还原凭据，也不出现在任何接口应答里。

| 级别 | 问题 | 处理 |
| --- | --- | --- |
| P2 | 凭据字段名检查要求完全相同，`api_key`、`vr-token` 这类带分隔符的写法拦不住；名单缺 `apiSecretKey`、`mnemonic` 等 | 已修：比对前去掉分隔符；名单补 `apiSecretKey`、`secretKey`、`password`、`mnemonic`、`seedPhrase`、`accessToken`、`authToken`。用例见 `test/asset-import.test.ts` |
| P2 | 交易所报错原文（`error`）是自由文本，可能带钱包地址或密钥 | 已修：各交易所状态与 Aster 账号的 `error` 里，钱包地址与 64 位十六进制串导入时隐去，其余文字保留 |
| P2 | `/api/asset/state` 第一次读取就 500 时不显示“资产”标签，用户看不到原因 | 已修：只有 404 才隐藏；500 时标签照常显示，页面说明原因 |
| P2 | 读库失败的应答带底层报错原文，JSON 解析错误会带出一段库内文本 | 已修：JSON 解析错误只说“库里有一项数据格式无效，请重新导入” |
| P2 | `scripts/asset-demo.ts` 不检查目录，误传真实数据目录会用示例数据替换已导入的账本 | 已修：只接受空目录或带本脚本标记文件的目录 |
| 建议 | 删掉 `asset.sqlite` 再导入后，服务继续读已删除的旧文件 | 已修：每次读取比较文件标识，变了就重新打开 |
| 建议 | 回滚自身报错会盖住原始报错 | 已修 |
| 建议 | 一次应答由多条 SQL 拼成，导入恰好在中间提交时会混有新旧数据 | 登记，未修：下一次读取即恢复，导入是偶发的人工操作 |
| 建议 | 资产行、快照、出金备注与资金流记录里的自由文本（含用户手填的“账户标识”）原样导入并显示 | 登记，未修：与工作台页面显示的内容相同；`docs/asset.md` 已写明这一例外 |
| 建议 | 资产行或快照里出现 `label`、`address`、`token` 字段名不会被拦 | 登记，未修：这些名字在账本数据里可能有正常用途，工作台当前数据里没有 |
