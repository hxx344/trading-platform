## 结论

两路审查都没有 P0。合约没有发现资金损失路径：合约不持有本金，第一跳输入须在同一笔交易内付清，回调只认本次调用登记的池子，池子向登记过的工厂核对。

### 合约与资金路径

| 级别 | 问题 | 处理 |
| --- | --- | --- |
| P1 | 过期未上链的交易没有出口：同一 nonce 上累计 3 笔即停实盘，重新开始后一发现机会又停；加价的底只升不降，几次之后小机会永远「净利不足」 | 已修：过期笔数按本次实盘会话计；加价只以 10 分钟内发出的同 nonce 交易为底，节点答 replacement underpriced 时改按全部未结清交易加价 |
| P1 | 白名单移出代币后，内存里的池子与环路要等下次目录刷新才变；刷新失败沿用旧目录时移出不生效 | 已修：移出立即过滤池子并重建环路；刷新结果按当前白名单过滤，刷新期间白名单有改动则标记目录过期；发送前再核对路径上的代币 |
| P2 | 节点返回的已上链交易数落后于已拿到的回执时，后面的交易会被算进「nonce 被占用」而误报故障 | 已修：nonce 不大于本模块已上链最大 nonce 的无回执交易记为「被替换」；节点 nonce 落后时这一轮不发 |
| P2 | 小费只按利润比例取，没有绝对上限；模拟利润很大或 ETH 价被读低时一笔可花光当日预算 | 已修：单笔小费合计不超过每日 gas 预算的 25% |
| P2 | 测试缺口：过期后重新开始、加价窗口、白名单即时生效 | 部分已修：补了加价窗口、白名单移出即时生效的断言。过期熔断后重新开始再发送的用例未补，登记在「未覆盖」 |
| P3 | 文档写「上链即不亏」，实际费用与折价都是发送前的测算值 | 已修：改为「大致不亏」并说明出入来源 |
| P3 | 合约核对只在启动与开始实盘前做；核对不过时整轮返回，已发出的交易不再结清 | 已修：实盘中每 10 分钟重做核对；结清挪到核对检查之前 |
| P3 | v3 池子部分成交时合约里可能留下中间代币的零头 | 未改：零头留在合约里，owner 可用 `rescue` 取回，不影响本金安全；登记 |
| P3 | OP 回执里的 `operatorFee` 没有计入实际费用 | 未改：Base 目前该项为 0；登记，待实测一笔后对照回执决定 |

### 凭据、部署、接口与页面

| 级别 | 问题 | 处理 |
| --- | --- | --- |
| P2 | `mev.sqlite` 没有绑定热钱包与合约：换钱包后旧钱包留下的未结清交易拿新钱包的 nonce 核对，会卡住或误报 | 已修：库里记身份，启动时不同则把旧的未结清交易记为「丢失」并清计数与故障 |
| P2 | `--unset-mev` 在不带本模块的旧版本上执行时会联网升级 | 已修：`--unset-mev` 始终沿用已装版本 |
| P2 | 开始实盘的确认没有绑定页面所见：旧页面的请求会清掉用户没看到的故障记录 | 已修：请求带 `fault`、`haltReason`，与服务端不一致返回 409 `stale` |
| P2 | 停服时没有中止在途的节点请求，停服过程中仍可能签名发送 | 已修：停服先 `quiesce` 再中止请求 |
| P2 | 接口测试里「不带执行头被拒绝」实际停在 401，没有走到 csrf 检查 | 已修：登录后不带执行头断言 403 `csrf` |
| P2 | 测试缺口：库打不开时的 503、带 mev 的导入计划、安装测试里 `--unset-mev` 不升级与部分分支、只读令牌不能读 `/api/mev` | 未补，登记在「未覆盖」 |
| P3 | http 节点地址的放行名单把 100.0.0.0/8 整段当内网 | 已修：收紧到 100.64.0.0/10 |

| P3 | `mev-fork-check.ts --rpc` 的值留在命令行历史 | 已修（文档）：只填不带密钥的公共节点 |
| P3 | 帮助文本与文档没写服务器上 `deploy-data.ts` 的路径、`--set-mev` 可能先升级 | 已修 |
| P3 | 库打不开时模块不启动，只写日志、不发通知 | 未改：页面与接口返回 503，日志有原因；登记 |
