## 独立审查

两轮，每轮新开只读审查者，只给差异范围、[审查标准](../code-review.md)、方案文档与核查重点。第一轮看 `5a53bd7..027408b`，第二轮只看修复提交 `027408b..c61161b`。两轮都没有 P0；第一轮 1 条 P1，第二轮没有 P1。

已核实的要点：带 `Authorization` 的请求在 `/login`、页面、静态资源、会话校验和令牌管理接口之前进入令牌分支，令牌换不到 cookie；HEAD、OPTIONS、小写 `bearer`、尾部斜杠、百分号编码路径都被拒绝，白名单判断与路由用同一个 URL；白名单接口的全部应答（包括错误应答）都经过打码，没有直接 `pipe` 或 `end` 的出口；白名单接口不触发交易所请求（CrossEx 不放行 `funding`），应答里没有私钥、API 密钥、webhook、会话或 Variational token；令牌比较定长、到期与吊销立即生效、损坏的令牌文件不接受任何令牌、限额在中断与出错时都会释放、审计行不含令牌；拆分部署下来源地址只取控制进程从套接字填写的值。

| 问题 | 处理 |
| --- | --- |
| P1，白名单接口的真实应答没有以令牌身份逐个核对打码与外发请求 | 部分修复：执行器状态、划转历史、ADL 事件、Ondo 状态用真实视图读取并比对会话应答里的全部标识原值，Ondo 读取期间交易所客户端调用为 0；其余登记为下面的 P2 |
| P2，`/api/status`、`/api/logs` 与 CrossEx、期权、行情监控、原油与海力士的令牌读取没有用真实视图逐个核对 | 登记：目前由字段表与按值规则覆盖；下一次改这些模块的状态应答时补上，见 [mcp.md](../mcp.md) 第 7 节 |
| P2，被拒的令牌请求也算作「最近使用」 | 已修：只计令牌校验通过的请求，补了测试 |
| P2，错误令牌的锁定整个进程共用，锁定期间每个请求都写日志 | 已修：按来源地址分别计数（最多 1024 个地址），锁定期间的请求不写日志，补了测试 |
| P2，拆分部署下 `/api/update` 由控制进程作答，不经过打码 | 已修：令牌读取在线更新状态在两种部署下都只得到不含自由文本的投影，补了单进程与拆分部署两项测试 |
| P2（第二轮），金额排除条件过宽：UID 后紧跟半角标点或 `USDT-M`、`U本位`、`个人` 等时不再打码 | 已修：只有小数点或千分位后仍是数字才算金额，单位后要求词边界，中文单位只留 `美元`、`元`、`%`；七个样例写进测试 |
| P2（第二轮），文档写的真实视图覆盖范围大于实际 | 已修：第 7 节按实际范围改写，`status`、`logs` 列入登记的 P2 |
| P3，`子账户 50000 USDT` 这类金额与 `users: 3` 这类计数被换成别名 | 已修 |
| P3（第二轮），“令牌读取不向外发请求”的断言替换的是全局 `fetch`，不可能失败 | 已修：改为对替身交易所客户端计数 |
| P3（第二轮），测试的原值收集复述了实现里“哪些字段的数字算编号”的规则 | 已修：标识字段下的数字一律视为原值，只豁免明确的计数字段 |
| P3，拒绝应答的审计行字节数记为 0 | 不改：拒绝应答是固定的短文案 |
| 残余限制，经回环隧道或共享 NAT 访问时多个客户端共用一个来源地址，可能互相锁住 | 不改：按文档经 Tailscale 直连不受影响 |

第二轮的修复之后没有再做独立审查，只重跑了类型检查、相关测试与全套测试。
