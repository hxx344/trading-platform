### 1.3 资金与凭据边界

- **热钱包（operator）**：私钥由页面录入、存在数据目录的 `mev-wallet.json`（v0.85.0，见 1.9），或在密钥文件的 `mev.privateKey`（`--set-mev`）。只用于部署执行合约（页面启用时）和调用它的 `execute`。钱包里只放 gas（建议 0.01–0.02 ETH）。**这把钥匙泄露或程序出错的最大损失是钱包里的 gas 余额。** 必须专用：配置检查拒绝它与任何 ASTER 账户的钱包或签名钱包、与 owner 或合约地址相同。私钥不出现在日志、页面、接口应答与报错里。
- **所有者（owner）**：用户自己保管的另一个钱包地址（页面上叫「利润收款地址」），部署时写进合约的不可变量，私钥不进本服务。只有 owner 能更换 operator、登记或注销工厂、取回合约里的代币。
- **利润去向**：每笔成功的套利在同一笔交易里把起始代币余额全部转给 owner，合约不留余额。operator 没有任何提币入口。
- **合约约束**：
  - `execute(hops, amountIn, minProfit, deadlineBlock)` 只有 operator 可调；区块号超过 `deadlineBlock` 回滚（`Expired`）；结束时起始代币增量小于 `minProfit` 回滚（`NoProfit`）。
  - 每一跳的池子都向登记过的工厂查询核对（v3 用 `getPool(token0, token1, fee)`、Slipstream 用 `getPool(token0, token1, tickSpacing)`、Aerodrome v2 用 `isPool`），对不上回滚（`BadPool`）。没有用初始化代码哈希推算地址，省去一组要核对的常量。
  - 回调（`uniswapV3SwapCallback`、Aerodrome v2 的 `hook`）只接受当前正在兑换的那个池子，其他调用者回滚（`BadCallback`）。
  - 不可升级、无 `delegatecall`、无任意外部调用入口。
- **节点地址**：可能带服务商密钥，和私钥一样放在密钥文件的 `mev.rpcUrl`（可另有只用于发送的 `mev.sendRpcUrl`）。须为 https，本机或内网自建节点可用 http。页面、日志、报错里只出现主机名或不出现。
- **代币**：环路起止只用 WETH 与 USDC；中间代币按白名单，首次启动写入 cbBTC、AERO、cbETH、wstETH、DAI、USDT（从链上读到符号与精度的才加入），页面可增删，最多 24 个。转账收税、可暂停、黑名单类代币即使混入，也由结尾的余额检查拦下（最坏结果是回滚、亏 gas）。
- **不做的事**：不做夹击（sandwich）与抢跑他人交易。本模块只在区块落定后回补池子之间的价差。

### 1.4 风控

页面「设置」可改，保存即生效，存在 `mev.sqlite`。

| 项 | 默认 | 说明 |
| --- | --- | --- |
| 最低净利 | 0.30 美元 | 模拟利润扣掉 L2 gas、L1 数据费与小费之后 |
| 净利对基础费用倍数 | 2 倍 | 净利至少是 L2 基础费加 L1 数据费的这么多倍 |
| 小费占利润比例 | 30% | 预期利润里拿去做优先费的部分；最低 0.001 gwei。单笔小费合计（按 gas 上限算）不超过每日 gas 预算的 25%：模拟利润很大或 ETH 价被读低时，一笔也花不光当日预算。同 nonce 替换交易的加价在封顶之后，可以超过它，仍受每日预算检查约束 |
| 链上最低利润比例 | 50% | `minProfit` 取模拟利润的这个比例，且不低于这笔按测算的费用（上链时大致不亏，否则回滚；费用与起始代币折 ETH 的价格都是发送前的测算值，回执里的 L1 数据费可能略有出入） |
| 单笔 gas 上限 | 1,200,000 | gas 上限取估算的 1.3 倍，超过这个数的环路不发；费用上限为基础费 3 倍加小费 |
| 每日 gas 预算 | 0.003 ETH（UTC 日） | 已结清支出加未结清交易的最坏预留；放不进剩余预算的这一笔跳过，真的用完则停实盘并通知 |
| 连续回滚熔断 | 5 笔 | 连续上链回滚即停实盘 |
| 钱包余额下限 | 0.002 ETH | 低于即停实盘并通知 |
| 单笔名义上限 | 50,000 美元 | 第一跳输入的上限。原子回滚下不是亏损上限，只限制对池子的冲击 |
| 粗筛毛收益门槛 | 5 基点 | 现货价上的环路毛收益超过它才模拟 |
| 池子最小深度 | 20,000 美元 | 两侧虚拟储备合计低于它的池子不参与 |
| 每区块模拟条数 | 3 条 | 每条约 10 次 `eth_call`，按节点配额调 |

发送与恢复（`src/mev/sender.ts`、`engine.ts`；按 LESSONS L039、L049、L089、L091、L093、L206 核对后落实）：

- **先入库再发送**：nonce、哈希、原始交易、最坏费用写进 `mev.sqlite` 后才发。同一时刻只有一个 nonce 在途。
- **结果不明不重发**：发送超时、断连或被节点拒绝都记为「结果不明」，不换 nonce 重发。结论只来自同一批读取里的回执、热钱包已上链交易数与节点最新区块号。
- **没有回执不等于没上链**：nonce 未被占用且节点区块已越过 `deadlineBlock` 加 15 个区块，才记为「已过期未上链」（此后即使上链也只会因过期回滚）。之后才允许在同一 nonce 上发替换交易，两项费用至少加 25%。加价只以 10 分钟内发出的同 nonce 交易为底；更早的过期交易节点多半已丢弃，不再抬价，节点答「replacement underpriced」时改按全部未结清的同 nonce 交易加价。本次实盘期间同一 nonce 上过期 3 笔即停实盘；重新开始实盘后重新计数，旧的过期交易不会让它一发现机会又停。
- **节点读数落后于回执**：热钱包已上链交易数不大于本模块已上链交易的最大 nonce 时，这一轮不发；查不到回执但 nonce 不大于它的旧交易记为「被替换」，不算进「nonce 被占用」。
- **nonce 被外部占用**：链上 nonce 已前进，却连续 5 轮查不到本模块任何一笔的回执，记为「nonce 被占用」并写入故障记录，停实盘。故障记录跨重启保留，在页面重新开始实盘（确认提示里会显示它）时清除。
- **节点连续拒收** 3 次、**节点持续不可用** 60 秒：停实盘。
- **节点落后**（最新区块时间戳比本机慢超过 6 秒）时不发交易，也不能开始实盘。
- **重启**：库里未结清的交易照上面的规则继续核对；「已入库待发送」的那一笔不重发，等它过期。
- **换了热钱包**：库里记着上次的热钱包地址。启动时发现不同，旧钱包留下的未结清交易直接记为「丢失」（原因写明已更换），连续回滚计数与故障记录清零；旧钱包的上链记录不参与新钱包的 nonce 比较。只换执行合约时 nonce 空间没变，未结清交易与故障记录照常核对。
- **合约核对**：启动时、开始实盘前各做一次，实盘中每 10 分钟重做一次；读到不符即停实盘，读不到结果（超时、缺项）时下一轮重试，连续 3 次读不到才停。核对不过期间仍继续结清已发出的交易。
- **白名单改动**：移出代币立即从内存里的池子与环路里去掉；发送前再核对一遍路径上的代币都在白名单里，目录刷新失败沿用旧目录时也按当前白名单过滤。
- **停服**：收到停止信号即不再签名与发送，并中止在途的节点请求；已发出的留在库里，下次启动核对。
- 热钱包由本服务进程独占；服务本身已有单实例写入租约，本模块不另设写者。

### 1.5 失败时会怎样与怎么回滚

- **套利没抢到 / 状态变了**：交易回滚，亏这一笔的 gas；计入每日预算与连续回滚计数。
- **合约有缺陷**：合约不持有本金，第一跳的输入在同一笔交易内必须付清，否则整笔回滚；可损失的仍是 gas。发现缺陷时在页面停实盘，owner 调 `setOperator(0)` 即停用旧合约，重新部署后用 `--set-mev` 换地址。
- **私钥泄露**：损失上限为钱包 gas 余额；owner 更换 operator。
- **服务层回滚**：回到 **v0.83.0**。回退前在页面停实盘，再执行 `sudo bash install.sh --unset-mev`（当前版本下执行；它只改两个文件并重启服务，不换版本、不联网）把 `mev` 从 `config.json` 与密钥文件里去掉：旧版本不认识这两个键，配置检查会失败。`mev.sqlite` 留在数据目录，不影响其他模块，重新升级接着用。链上合约与热钱包不受版本回退影响。已登记在 [README](../README.md)《回退到旧版本》。

### 1.6 配置

- `config.json`：`"mev": { "executor": "<执行合约地址>", "owner": "<利润收款地址>" }`。有这个键才开模块。
- 密钥文件：`"mev": { "rpcUrl": "<节点地址>", "privateKey": "0x…", "sendRpcUrl": "<可选，发送专用节点>" }`。
- 两处都由 `install.sh --set-mev` 写入，不要求手改。这是 v0.84.0 的启用方式，继续支持；用它时页面不能录入、换节点或移除（接口返回 409 `managed`），数据目录里的钱包文件不被采用。
- 页面启用（v0.85.0，默认方式）：不动 `config.json` 与密钥文件，见 1.9。
- `--check-config` 的输出在开启时多一段「MEV 套利（Base，执行合约 0x…，热钱包 0x…）」，地址只显示首尾。

### 1.9 页面启用（v0.85.0，R3）

2026-11-25 用户决定：命令行启用太复杂，只想在页面输入一次私钥。同日确定两项：利润打到另填的一个收款地址；节点默认用 Base 公共节点，可选填自己的。

**做法**

- 页面录入三项：热钱包私钥、利润收款地址（owner）、节点地址（可不填，默认 `https://mainnet.base.org`）。保存后页面显示热钱包地址与余额；用户向它转入 gas 后点「部署执行合约」，由热钱包签名并发出部署交易（`to` 为空，data 即 `deploy-data.ts` 的输出）。上链后服务读合约地址上的代码，与本版本产物按 owner 填好不可变量后的运行时代码逐字节相同才采用，随即以观察模式启动引擎。实盘仍须在页面另行确认开始。
- 合约约束不变：owner 不可变，热钱包只是 operator，没有提币入口；利润每笔直接转给 owner。由热钱包而不是冷钱包部署不改变这些，部署者在合约里没有任何特权。
- 存放：数据目录的 `mev-wallet.json`，`{ privateKey, owner, rpcUrl?, executor?, deploy? }`，服务账户所有、权限 600，先写临时文件并落盘（fsync）再改名（没有 fsync 目录：断电丢了改名时，重启后按「沿用已部署的合约」的扫描找回）；写到一半被杀留下的临时文件在启动与移除时清掉。执行服务的 systemd 单元只允许写数据目录，写不了 `config.json` 与密钥文件，所以不放那两处。启动时若热钱包与某个 ASTER 账户的钱包或签名钱包相同（录入后才加的账户），不采用并在页面说明（文件仍在磁盘上，录入新的专用钱包会覆盖它）。改用 `--set-mev` 后这个文件不再被读取，但仍留在数据目录；不想留就先在页面移除热钱包再执行 `--set-mev`，或手动删除。
- 合约地址由热钱包地址与 nonce 决定（CREATE）。部署记录先落盘再发送；发送超时或断连时保留记录并在页面写明「结果不明，正在核对」，继续按地址核对。5 分钟没上链可在同一个 nonce 上加价 25% 以上重发，不论哪一笔上链地址都一样；重发只在节点读到的 nonce 等于原记录的 nonce 时进行（更大返回 409 `pending` 等核对，更小返回 409 `node_behind`）。节点明确拒收时恢复发送前的记录：首次发送即撤掉、可以马上重试，重发则保留原来那笔。链上 nonce 已越过部署交易、地址上却没有预期代码，连续 3 轮（读不到代码的轮次不算，容忍落后的节点）判定部署没成并在页面说明，可以重新部署。
- 沿用已部署的合约：候选是移除时留下的地址（`mev-contract.json`，`{ operator, owner, executor }`，不含私钥，热钱包与 owner 都相同才用）加上这个钱包最近 16 个 nonce 的 CREATE 地址。地址上的代码与本版本按 owner 填好的运行时代码相同、且合约的 `operator()` 仍是这个热钱包才沿用（owner 用 `setOperator` 停用过的旧合约不沿用）。每批查 4 个地址，并在同一批里再读一次 nonce；链上 nonce 变化后重新查；有读不到的、或某一批读到的 nonce 与开始时不同（节点后端进度不一），就不算查完。部署请求在签名前自己再查一遍：找到就沿用、不发交易，读不全返回 502、不发。超出这两类候选的旧合约不会被找到，会重新部署一个（多花一次部署费用，旧合约不受影响）。
- 更换节点、移除热钱包在向导的第 2、3 步与「设置」页签的「热钱包与节点」卡片里都能做；实盘中两者都拒绝（409 `live`），服务停止过程中拒绝（503 `stopping`）。部署在途时也可以移除或换节点：那笔交易之后仍可能上链并花掉 gas，移除时服务器记下它将落在的合约地址，重新录入同一把私钥与收款地址后一旦上链即沿用。移除即删掉钱包文件；之后录入另一把私钥时，引擎按 1.4「换了热钱包」的规则结清旧钱包留下的交易。
- 每换一次钱包或节点，旧引擎停止签名、在途的节点请求被中止、关库后再用新身份启动，回到观察模式。

**凭据边界的变化（本次的主要风险）**

- 私钥此前只经 root 的终端进密钥文件；现在经页面 → 控制服务 → 执行服务。控制服务只转发请求体，不落盘、不记录；执行服务的接口与报错不回显请求体。写接口沿用全站的登录与 `x-pa-executor` 检查，只读令牌不能写。
- 页面经明文 http 且不是本机地址打开时，录入表单上方有警告（私钥会明文经过网络）；不强制拦截，因为站点是否走 https、是否只在内网由部署决定。
- 私钥以明文存在数据目录（与密钥文件一样是明文，属主是服务账户而不是 root）。能读数据目录的人能拿到它；损失上限仍是热钱包里的 gas。
- 状态接口只给热钱包地址、收款地址与节点主机名；日志与飞书通知里只有地址。录入、部署完成、移除各发一条通知，便于发现不是本人做的改动。
- 热钱包必须专用：录入时拒绝与任何 ASTER 账户的钱包或签名钱包相同、与收款地址相同。
- 默认公共节点不带密钥、有限速：够启用与观察；实盘建议换成自己的节点。

**失败与回滚**

- 填错收款地址：部署前「移除热钱包，重新录入」即可；部署后 owner 不可更改，只能移除后用新的收款地址重新录入并重新部署（再花一次部署的 gas）。部署前的确认框会再显示一遍收款地址。
- 钱包文件损坏或读不懂：模块回到未录入并在页面写明，不影响执行服务其他部分；重新录入会覆盖它。
- 回到 **v0.84.0**：先在页面停止实盘。v0.84.0 不读 `mev-wallet.json`，回退后「MEV 套利」页消失、引擎不再运行，文件与 `mev.sqlite` 留在数据目录，重新升级接着用；不想让私钥留在服务器上就在回退前到「设置」页签移除热钱包。用 `--set-mev` 启用的不受影响。已登记在 [README](../README.md)《回退到旧版本》。

**改动的文件**：新增 `src/mev/setup.ts`、`web/src/mev/MevSetup.tsx`、`test/mev-setup.test.ts`；改 `src/service/mev.ts`（重写为管理器）、`src/service/main.ts`（模块总是加载）、`src/http.ts`（四个启用接口）、`src/mev/codec.ts`（`to` 可为空的创建交易）、`src/mev/views.ts`、`src/mev/fake-chain.ts`、`src/service/mev-config.ts`（导出 `validRpcUrl`）、`web/src/mev/MevPage.tsx`、`mev-form.ts`、`scripts/dev-mev.ts`。不改合约、引擎、风控、库结构与安装脚本。

## 2 机会发现与执行

每一轮（`engine.ts` 的 `tick`）：

1. **读最新区块**，区块没变就不重复计算。
2. **结清**：读一次热钱包的 nonce、余额与全部未结清交易的回执，能下结论的结清（1.4）。
3. **池子目录**（每 10 分钟刷新）：白名单代币两两组合，经 Multicall3 向三个工厂按各自的费率档 / tickSpacing 查池子地址，读两种代币与费率，存进 `mev.sqlite`。
4. **池子状态**：每个区块一次 Multicall3 批量读（v3 类读 `slot0` 与 `liquidity`，v2 读储备）。由池子状态推出代币的美元价与池子深度，过浅的池子不参与。
5. **粗筛**：对每条环路（两跳与三跳，最多 6000 条，超出时丢的是三跳；合约本身接受 2 到 4 跳）用现货价与手续费算毛收益，取超过门槛的前几条。粗筛只是筛选，不作为发送依据。同一条环路模拟后不盈利的，30 秒内不再模拟。
6. **模拟定量**：对候选环路取一组输入金额，用 `eth_call` 调执行合约（`from` 为热钱包，`minProfit` 为 0）得到每档的实际利润，围绕最优一档再细分一轮，取最优。
7. **费用**：`eth_estimateGas` 估 L2 gas；向 OP 预部署的 GasPriceOracle 读这笔交易的 L1 数据费。
8. **测算与风控**：`planTransaction` 给出小费、费用上限、`minProfit` 与净利；`gate` 做账户级检查（1.4）。
9. **发送**（仅实盘）：`deadlineBlock` 取当前区块加 2，签名、入库、发到节点（配置了 `sendRpcUrl` 时走它）。
10. **记账**：回执里取实际利润（合约的 `Executed` 事件）、gas 用量与费用（含回执的 `l1Fee`）。

观察模式跑到第 8 步，把「本应发送」的机会与模拟净利记下来（同一条环路每 30 秒记一行）。它不知道真实上链时是否被别人抢先，所以观察利润是上限，不是预期收益。

启动时与每次开始实盘前核对执行合约：链上运行时代码与本仓库产物（按 owner 填入不可变量后）逐字节一致，合约的 `owner()` 与配置一致，`operator()` 是热钱包。任何一项不符，模块停在这一步（不读池子、不模拟、不发送，实盘中则停实盘），每 60 秒重试核对，页面显示原因。

## 3 对结果的预期

- 主流池子之间的简单环路，是专业搜索者用同机房节点、Flashblocks 数据和更优的合约在毫秒级竞争的领域。本模块第一版按区块轮询、经普通 RPC 发送，**大概率抢不到主流池子的机会，收益主要可能来自长尾池子，也可能长期接近零甚至净亏 gas**。风控默认值按「先小额试错」设置，每日最多亏 0.003 ETH。
- 是否值得继续投入（Flashblocks、自建节点、更多池型），以观察与实盘两周的数据为准：发现次数、模拟利润分布、上链成功率、被抢先比例，这些都在页面上。
- 公共节点限流严，只够观察；实盘需要自备 Base 节点或付费 RPC。

## 5 页面与接口

工作台没有同功能页面；骨架与样式沿用本仓库的 Var/Lighter 价差页（`varlighter.css`、`parts.tsx` 的 `Badge` / `Metric` / `useWrite`），`mev.css` 只有十几行本页特有的排版。回退版本 v0.83.0。页签都在地址里：

- **概览**（`#/mev`）：模式与开始 / 停止按钮；合约核对结果；热钱包地址、余额与 nonce；今日 gas 支出、预留与预算；今日利润与观察到的机会；最新区块与落后情况；熔断原因与故障记录。
- **机会**（`#/mev/opportunities`）：最近的机会（环路、毛收益、利润、费用、净利、处理结果与原因）。
- **交易**（`#/mev/transactions`）：已发送交易（哈希链到 basescan、状态、费用、实际利润）。
- **池子与代币**（`#/mev/pools`）：受监控池子与深度；代币白名单增删（起始代币固定）。
- **设置**（`#/mev/settings`）：1.4 的风控参数；「热钱包与节点」卡片（地址、节点主机名、更换节点、移除热钱包；由配置文件管理时只读）。

引擎没在运行时（还没录入、等待部署、启动失败）不显示页签，整页是启用向导：第 1 步录入，第 2 步转入 gas 并部署，第 3 步等待上链。

「开始实盘」有确认提示，写明热钱包地址与余额、合约、利润收款地址、每日 gas 预算、最低净利、熔断笔数，以及上次的故障记录或停止原因；请求须带上热钱包地址（`confirm`）和页面当时显示的故障记录与停止原因（`fault`、`haltReason`），服务端再核对一遍合约、节点与余额。故障记录或停止原因与服务端当前的不一致（页面是旧的）时返回 409 `stale`，不清除故障，刷新后重新确认。

| 接口 | 作用 |
| --- | --- |
| `GET /api/mev/state` | 页面全部读数，另有 `setup`（阶段 `none` / `wallet` / `deploying` / `ready`、是否由配置文件管理、热钱包与收款地址、节点主机名、余额与 nonce、在途的部署、错误）。引擎没在运行时只有 `setup`。不含私钥与节点地址 |
| `POST /api/mev/setup` | `{ privateKey, owner, rpcUrl? }` 录入；已录入时 409 `exists` |
| `POST /api/mev/setup/deploy` | `{ confirm: <热钱包地址> }` 发出部署交易（找到已部署的合约时直接沿用、不发）；余额不够 409 `low_balance`，在途未满 5 分钟或 nonce 已用掉 409 `pending`，上一次请求未结束 409 `busy`，节点落后 409 `node_behind`，节点拒收 502 `rejected`，读不全 502 `rpc`，已部署 409 `deployed`，签名前的读取途中钱包或节点被改 409 `stale`（发送途中被改按当前状态返回），服务停止中 503 `stopping`。页面给这个请求 45 秒超时（其余写请求 15 秒） |
| `POST /api/mev/setup/rpc` | `{ rpcUrl }` 更换节点，`null` 或空改回公共节点；实盘中 409 `live` |
| `POST /api/mev/setup/reset` | `{ confirm: <热钱包地址> }` 移除热钱包（部署在途时也可以）；实盘中 409 `live` |
| `POST /api/mev/settings` | `{ settings }` 保存风控参数，范围由服务端校验 |
| `POST /api/mev/live/start` | `{ confirm: <热钱包地址>, fault, haltReason }` 开始实盘；后两项是页面所见，可为 `null` |
| `POST /api/mev/live/stop` | 停止实盘 |
| `POST /api/mev/tokens` | `{ action: 'add' | 'remove', address }` 改白名单 |

引擎没在运行时，引擎的接口（settings、live、tokens）返回 503 `unavailable`；由配置文件管理时四个启用接口返回 409 `managed`。写接口沿用全站的登录与 `x-pa-executor` 检查。只读 MCP 未接入本模块。

本地预览：`pnpm build:web` 后 `node scripts/dev-mev.ts`（替身节点，不联网，热钱包私钥启动时随机生成）；加 `--setup` 从还没启用开始看启用向导，用脚本打印的公开测试私钥。

## 6 启用（账户持有人本人做）

### 6.1 在页面启用（v0.85.0 起的默认方式）

1. **建专用热钱包**：新建一个地址，不与任何其他用途共用，导出它的私钥并自己留好备份。
2. 打开「MEV 套利」页，填**热钱包私钥**与**利润收款地址**（你自己保管的另一个地址），节点地址可不填，点「保存热钱包」。站点不是 https 时在内网、Tailscale 或服务器本机打开本页再填。
3. **给热钱包转入 0.01–0.02 ETH**（Base 链）。页面显示余额到账后点「部署执行合约」并确认（确认框里再核对一遍收款地址）。
4. 部署上链后页面自动进入观察模式。看一段时间的机会与模拟净利，确认合约核对通过。
5. **开始实盘**：点「开始实盘」并确认。

更换节点、移除热钱包在「设置」页签。实盘建议换成自己的 https 节点（公共节点有限速）。

### 6.2 用命令行启用（v0.84.0 的方式，继续支持）

适合不愿让私钥经过页面、或要用冷钱包部署合约、或要另设发送专用节点的情况。用了它，页面上的录入与移除不可用。步骤：

1. **准备节点**：一个 Base 主网的 https RPC。
2. **建专用热钱包**：新地址，不与任何其他用途共用；记下地址，私钥只在第 4 步输入。
3. **部署执行合约**（冷钱包）：
   ```
   node src/mev/deploy-data.ts --owner <冷钱包地址> --operator <热钱包地址>
   ```
   在仓库目录下执行；服务器上这个文件在 `/opt/trading-platform/current/src/mev/deploy-data.ts`。它只做编码，把部署交易的 data 打到标准输出。用自己的冷钱包发一笔 `to` 为空、`value` 为 0、data 为这串内容的交易到 Base 主网（例如 `cast send --rpc-url <节点> --ledger --create <data>`）。记下部署出的合约地址。
4. **启用**（服务器上）：
   ```
   sudo bash install.sh --set-mev --mev-executor <合约地址> --mev-owner <冷钱包地址>
   ```
   依次不回显地输入节点地址、发送用节点地址（可空）、热钱包私钥。脚本化时加 `--mev-stdin` 从标准输入读这三行。之后再执行时，空行沿用已保存的那一项，发送用节点地址填 `-` 表示去掉。写入前按服务启动的规则完整校验，随后用新程序检查配置，检查不过时两个文件放回原样。输出只有地址与节点主机名。
5. **给热钱包转入少量 ETH**（Base 上，0.01–0.02）。
6. **先观察**：打开「MEV 套利」页，确认合约核对通过、余额正确，看一段时间的机会与模拟净利。
7. **开始实盘**：在页面点「开始实盘」并确认。

关闭：页面停实盘后 `sudo bash install.sh --unset-mev`。

`--set-mev` 需要已安装的版本带有本模块；当前已装版本不带时它会先升级到最新版本。只做设置、已装版本支持时沿用已装版本、不联网。`--unset-mev` 始终沿用已装版本。

节点地址须为 https；http 只接受 `localhost`、`127.0.0.1`、`[::1]`、10/8、192.168/16 与 100.64/10。
