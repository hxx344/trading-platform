# Ondo 挂单奖励模块：实施方案与现状

本文覆盖 2026-11-17 迁入的 Ondo Perps 挂单奖励模块，包含两部分：工作台「Ondo 挂单」模块的迁移，以及新增的奖励市场盘口与预期收益模拟。

- 对照的工作台代码：`project-aggregation` main `7745181`，即 `server/automation/ondo-mm.mjs`、`server/trading-ondo-{client,quote,stream}.mjs`、`server/exchange-transport/ondo.mjs` 和页面 `src/OndoMarketMakerPage.tsx`。
- 首发版本 v0.60.0；出问题回退 v0.59.0，做法见第 9 节。

### v0.62.0 变更范围与回退（R3）

- 前方保护量是同侧更优价位上其他人的挂单名义金额。开仓报价必须满足阈值，保护不足立即撤销余量。平仓走独立的只减仓路径。
- 实盘使用专用永续账户，在登录的 WebSocket 上启用交易所的断线撤单。它作用于整个账户的永续挂单。观察只读公开行情。
- 意外开仓成交（含部分成交）锁住整个会话的新增敞口，撤剩余开仓单并告警，根据已确认的仓位和用户保存的设置退出。平仓后须人工重新启用挂单。网络或订单状态未知时先核对。
- 观察模式在同一连续行情上比较 4、8、15 bps 的虚拟买单与卖单，记录有效挂单时长、触价与扫过；断线期间没有有效观察时间。单次观测不能证明真实成交或奖励收入。
- 回退版本为 v0.61.0。先停止会话，在 Ondo 核实撤单、处理剩余仓位并等断线撤单窗口结束，再回退软件。安装升级本身不启动实盘。实盘实际撤单时间、账户费率和奖励入账由账户持有人核实。

## 2 与工作台的差异

- **挂单编号前缀。** 本服务用 `tpo-`，工作台用 `omm-`。重启后由本服务逐笔清理时只认自己的前缀。交易所的断线撤单覆盖整个永续账户。
- **API Key 来源。** API Key 由 `readCredentials()` 从 `secrets.json` 读取，页面只显示末四位。
  - 没有 Key 时可以观察；开实盘返回 409，并提示去导入。
  - 原来的 `setKey`、`clearKey` 路由和加密文件 `credentials.json` 都去掉了。
- **导入设置的初始状态。** 导入的设置写在 `config.json` 的 `ondo.initial` 里，只在本服务还没有自己保存的设置时使用，并且总是以观察模式启动。
- **旧设置升级。** 保留市场、单量、价格距离和名义上限。原先关闭的前方保护会启用，原阈值为零时取默认 5,000 USD。旧设置首次读取时补入退出参数，实盘须按新确认页手动启动。
- **路由。** 路由前缀是 `/api/ondo/`。
  - `PUT config` 的请求体是 `{config}`；
  - `POST start` 收 `revision`、`confirmLive`、`confirmAccountWide`、`adoptPositions`。实盘需要两项确认均为 true。
  - `POST stop` 携带所见会话的 `sessionId` 和 `live`。若另一页面已经切换会话，返回 409 并保留当前会话。
  - `cleanup` 和 `recovery/discard` 的请求体为 `{}` 或空（仍须带 JSON 的 content-type 和请求标记）。
  - 有多余字段时返回 400「请求包含未知字段」。
  - `PUT` 请求同 `POST` 一样须带请求标记。
- **服务停止时。** 一收到停止就关掉奖励采集的推送连接和客户端（正在进行的盘口读取随之中止，不等它的 5 秒超时；推送没开满就停时，这一分钟的快照不记样本），同时开始撤实盘挂单，最多等 15 秒（`ONDO_CLOSE_WAIT_MS`），在 20 秒的排空期内完成。
- **客户端新增功能。**
  - `markets()` 带出 `makerFee`；缺失或格式异常时为 null，不报错。
  - 新增公开盘口 `depth(market, levels)`，不签名，并校验返回的市场名。
  - 奖励采集复用挂单引擎的推送客户端，只订阅公开盘口。连续观察另订阅公开成交。实盘连接登录后订阅账户和断线保护频道。

## 3 配置与密钥

```json
// config.json
"ondo": { "initial": { ...工作台挂单设置，mode 一律改为 observe } }   // initial 可省；只写 "ondo": {} 即启用观察
// secrets.json（可省）
"ondo": { "keyId": "…", "secret": "…" }
```

- 检查逻辑在 `src/service/ondo-config.ts`。
  - `config.json` 的 `ondo` 只允许 `initial` 一个键。
  - `secrets.json` 的 `ondo` 恰好两个字段，并且只有 `config.json` 里有 `ondo` 时才允许出现。
  - 报错信息不带字段值。
- `--check-config` 输出末尾会追加「Ondo 挂单奖励（API Key ***末四位）」，或「未配置 API Key，只能观察」。
- **本机进程锁。** 配置了 API Key 时，模块启动前先按 Key 加本机进程锁（锁名是 keyId 的摘要，`holdAccountLocks`，同原油、期权、CrossEx）。同一个 Key 已被本机另一个进程占用时整个服务不启动，并报「Ondo API Key ***末四位 已被本机另一个服务进程使用」。锁先于撤遗留挂单，所以第二个进程不会把第一个进程的挂单当成遗留撤掉。
- 运行时文件在 `<数据目录>/ondo-mm/`：
  - `config.json`：页面保存的设置；
  - `session.json`：实盘会话记录，用来在重启后撤销遗留挂单；
  - `rewards.json`：奖励市场设置。

## 4 实盘挂单

v0.62.0 的开仓单与只减仓单使用不同的报价条件。

- **开实盘的条件。** 需要同时满足：
  - 已保存的设置为实盘模式；
  - 页面确认实盘、账户级撤单范围与退出设置；
  - 版本号与已保存的一致；
  - 已配置 API Key；
  - 账户中的永续挂单已清空；
  - 账户里没有非本模块开的持仓，有持仓时须勾选「接管现有持仓」。
- **持仓读不到时。** 读不到持仓不当作空仓，返回 503。
- **重启后。** 只清理上次会话的 `tpo-` 挂单并核对账户持仓。实盘启动前写入未完成标记，正常停止须取得停止请求之后的新挂单和持仓读数。进程异常退出或旧版留下会话记录时，撤单和持仓核对照常进行，即使多次读到空仓，也须人工核实中断期间的订单及成交后才能解除恢复状态。剩余仓位显示市场、方向与数量，已配置飞书时推送告警。

**前方挂单量。** 金额按价格乘剩余数量逐档累加，排在拟报价同价的单不提供前方保护。实盘扣除账户自己的挂单。可行价格还须满足价格步长、最近及最远距离和名义金额上限。达不到保护金额时这一侧留空。已挂开仓单失去保护时发撤单，撤单送达撮合系统前仍可能成交。

**断线撤单。** 认证连接订阅 `cancelAllOrdersAfterPerps`，`timeout_seconds=30`。交易所确认前禁止下单，连接每 5 秒发 ping。真实断线、应答失效或保护被取消后暂停下单，尽力用 REST 撤单，留足前一次心跳的到期窗口再重连。主动停止也会先断开心跳。同一永续账户的手工挂单、只减仓单和其他程序的单都可能被撤，已有仓位仍须处理。[Ondo 永续断线撤单协议](https://docs.ondoperps.xyz/api-reference/private-channels/subscribe:-perps-dead-mans-switch)

**成交后的退出。** 开仓部分成交也会锁定所有市场的开仓，告警显示于页面，已配置飞书时通过现有通知通道投递。先按实际持仓挂只减仓 Maker 单。默认最长持仓 60 秒，最优可平价格相对入场均价不利变动 20 bps，任一条件触发退出。默认改用带限价的只减仓 IOC，允许的滑点为 10 bps。也可选触发后撤平仓挂单并转人工。流动性不足时 IOC 可能部分成交或零成交。亏损阈值用于触发退出，手续费、跳价和未能平掉的余量都会影响最终盈亏。处理完仓位后，需手动停止会话并重新确认才能开仓。[Ondo 下单协议](https://docs.ondoperps.xyz/api-reference/rest-spec.json)

**观察模式。** 同一段连续的公开盘口和 `tradesPerps` 逐笔成交驱动 4、8、15 bps 三档虚拟报价。每个市场的买卖两侧分别统计。主动卖出到达虚拟买价、主动买入到达虚拟卖价各为触价，严格越价还记一次扫过。每张虚拟单各最多记一次。以各行有效虚挂时长为分母，满 60 秒显示每小时次数。停止后保留本次观察结果供核对，进程重启会清空。盘口排队、实际网络和撮合时延需要真实账户记录才能验证。

观察按交易所时间整理最多 1.5 秒的乱序盘口与逐笔成交，同一毫秒先处理盘口，再处理成交。过迟或超出缓存容量的样本不参与该段统计。页面上的最近一小段时间可能随迟到成交修正。

专用账户出现其他永续挂单、整账户读取超过 15 秒未更新、连续三次撤单失败或撤单 15 秒仍未核清，都会停止续心跳，让交易所撤单倒计时到期。先前的空账户读数随新证据失效。只有在最后一次异常之后重新读完全部挂单和持仓，并确认账户无挂单，才允许重建受保护的连接。原开仓锁持续有效。

## 5 奖励市场采集（`src/ondo/rewards.ts`）

- **观察列表。** 默认 20 个市场（`REWARD_MARKETS`），与 Ondo 奖励公告一致。每周奖池默认 125,000 USD，参与分配的市场默认 20 个。这三项都可以在页面「奖励设置」里修改，保存在 `rewards.json`。
- **采样节奏（v0.61.0 起用 WebSocket 推送）。**
  - 每分钟开头订阅一次公开盘口推送 `depthBooksPerps`（`wss://api.ondoperps.xyz/ws`，不登录），订阅整个观察列表、每侧 100 档（`FEED_LEVELS`），开 10 秒（`BURST_MS`）后断开。
  - 推送期间每秒（`TICK_MS`）取各市场最新的一份盘口。同一份不重复取；到达已超过 2 秒的不取（推送对该市场停了）。每个市场每分钟约 10 份快照，原来是 1 份。
  - 只订阅交易规则里列出的市场：2026-11-17 实测，订阅里只要有一个 Ondo 不认识的市场，就回「provided market is invalid」，整条订阅都收不到数据。交易规则还没读到时照原列表订阅。
  - 推送期间没收到的市场（连接失败、交易所不推这个市场、交易规则里没有），在这一分钟剩下的时间里走 REST 读一次公开盘口（`GET /v1/perps/depth`，100 档；客户端每秒最多 2 个请求，读完一个再读下一个）。页面上这些市场的平均值后面标「REST」。整轮推送一份都没收到时，页面提示原因。
  - 交易规则（是否上市、能否交易、最小价格单位、挂单手续费）每 15 分钟读一次。
- **为什么是每分钟 10 秒。** 2026-11-17 实测：Ondo 对每个订阅的市场固定每秒推 3–4 次全量快照，数据不压缩。20 个市场持续订阅，每侧 100 档约 165 KB/s（每天约 14 GB），40 档约 110 KB/s（每天约 9.5 GB）。每分钟只开 10 秒，100 档均摊约 27 KB/s，每天约 2.4 GB。原 REST 方案每天约 0.1 GB。
- **为什么是 100 档。** 实测 XAU 近处档位很密（5 bps 内约 29 档），前 40 档只覆盖约 4–5 bps；US500、BTC 约 12–15 bps。100 档时这几个市场都覆盖到 100 bps 以上。推送每侧最多给 100 档，`limit` 填 0 或 200 也一样。仍不足 25 bps 时照旧按最远一档计，并在页面标出。
- **每次采样的处理。**
  - 中间价取 (买一 + 卖一) / 2。
  - 两侧各档按距中间价的 bps 归入 0.5 bps 宽的桶，共 50 个，覆盖到 25 bps。
  - 前 5 bps 的逐档明细最多保留 40 档。
  - 本模块自己的实盘挂单按价格从盘口里扣除，页面另列「自己」一栏，所以份额只拿别人的挂单来比。
- **覆盖距离。** Ondo 每侧最多给 100 档，盘口密时 100 档也可能不到 25 bps，所以不论返回多少档，覆盖距离都按返回的最远一档计；更远的桶按 0 计，会高估份额。覆盖不到 25 bps 时页面标出「盘口只覆盖到 X bps」（盘口本身就薄时也会标，偏保守）。
- **样本窗口。** 每个市场每分钟一个样本：这一分钟各份快照的分桶平均、最小覆盖距离和最后的中间价。样本保留 6 小时。页面可选 15 分钟、1 小时、6 小时窗口，看各桶的平均值，每分钟权重相同（REST 兜底的一分钟只有 1 份快照）。
- **1 分钟波动率。**
  - 每个市场记一个起点快照。之后的快照距起点满 5 秒时，取一次中间价对数收益，按 √(60 s/间隔) 折算到每分钟，再把它作为新的起点；距起点超过 120 秒时不算收益，直接换起点。
  - 推送时每分钟约 2 个收益：推送内 1 个 5 秒收益，加上跨到下一分钟推送的一个约 55 秒收益。REST 兜底时每分钟 1 个。
  - 窗口内全部收益的平方和取零均值的均方根。少于 20 个收益（`MIN_RETURNS`，推送约 10 分钟）时为空，此时模拟只算奖励，不算成交与亏损。
  - 5 秒收益会带入盘口闪动等微观噪声，测出的波动可能偏高，成交和亏损估算随之偏保守。
- **按需读盘口。** 单个市场展开时每 5 秒取一次盘口：推送期间直接用推送的最新快照，其余时间走 REST。每个市场至多 2 秒读一次，这类读取不计入样本；采集循环撞上正在进行的这类读取时共用它，并照常记一个样本。

## 6 预期收益模拟（`src/ondo/reward-sim.ts`，页面即时计算）

奖励部分按 Ondo 公布的规则计算，成交部分是本服务自己的模型，所有假设都作为页面参数列出。

| 量 | 公式 | 依据 |
| --- | --- | --- |
| 分数 | 每次快照：挂单金额 × e^(−k·距离 bps)，按距离分档：0–5 bps 85%，5–10 bps 10%，10–25 bps 5% | Ondo 规则；k 未公布，默认 0.1；设为 0 时同一档内不按距离衰减 |
| 每侧日奖池 | 每周奖池 ÷ 参与分配的市场数 ÷ 7 ÷ 2 | 各市场平分奖池；买卖两侧分别计分，本模型按每侧各占一半处理 |
| 份额 | 我的分数 ÷（同档他人分数 + 我的分数）；他人分数用时间窗内各桶的平均金额 × e^(−k·桶中心距离) | 平均深度近似每次快照的深度 |
| 日奖励 | 在线比例 × 每侧日奖池 × 档权重 × 两侧份额之和（选单边时只算买方） | |
| 日成交次数 | 在线比例 × 挂单边数 × (86400/τ) × 2(1−Φ(m/(σ_s·√τ)))，其中 σ_s = σ_1m/√60，m 为最近距离，τ 为撤单反应时间 | 中间价视为随机游走，用反射原理估算：在一次反应时间内价格走到最近距离，就算成交 |
| 每次成交亏损 | 挂单金额 × (σ_s·√H·√(2/π) + 2 × 挂单手续费率)，H 为平仓耗时 | 把平仓期间的期望绝对波动全部记为不利方向，偏保守；手续费按开平各一次挂单计 |
| 净收益 | 日奖励 − 日成交次数 × 每次成交亏损 | |

- **页面参数。** 每单金额、挂单距离、最近距离、撤单反应时间、平仓耗时、k、在线比例、单边或双边。
  - 默认值取当前挂单设置；不在挂单设置里的几项默认为反应 1 秒、平仓 60 秒、k 0.1、在线 95%、双边。
  - 参数只保存在本浏览器。
- **距离扫描。** 展开单个市场时，用 1–20 bps 九个挂单距离重算一遍，最近距离与挂单距离的间隔保持不变，最小 0.5 bps。
- **未建模的因素。** 包括：奖励的实际快照频率和最低金额门槛、排队位置、他人挂单随时间的变化、价格跳空、被成交后再挂单的空档、奖池的实际分配方式。这些因素都可能让结果偏离；本模块只用来比较各市场的相对吸引力，不承诺收益。

## 7 页面（`web/src/ondo/`）

- **上半部分。** 照工作台 `OndoMarketMakerPage` 排版（`OndoPage.tsx`、`ondo.css`），只是把「API Key」一栏改为只读说明。
- **奖励市场表（`OndoRewards.tsx`）。**
  - 列：市场、中间价、价差、1 分钟波动、前 5 bps 买 / 卖（当前值与窗口均值）、份额、奖励/日、成交/日、亏损/日、净收益/日。
  - 默认按净收益排序；表尾合计净收益为正的市场。
  - 每 15 秒刷新一次。
- **展开单个市场。** 显示买卖两侧前 5 bps 的逐档明细（价格、数量、金额、距离、累计、自己）和距离扫描表。
- **标签显示。** 导航「交易」组里的「Ondo 挂单奖励」只在服务启用了 `ondo` 时出现。

## 8 从工作台导入（`src/service/import-ondo.ts`）

- **读取的文件。** 以目录属主身份、在无环境变量的子进程里读取 `<工作台数据目录>/ondo-mm/{config.json,credentials.json,session.json}` 和 `<工作台数据目录>/credentials.key`。只读普通文件，单个文件不超过 64 KB，拒绝符号链接。
- **挂单设置。** 能通过校验就以观察模式写入 `config.json` 的 `ondo.initial`；通不过就跳过并说明，模块按默认值。
- **API Key。** 用工作台的 `credentials.key` 解密，写入 `secrets.json` 的 `ondo`。工作台存在 `session.json` 时不导入 Key：那表示工作台的实盘会话还在，或上次会话没有确认撤单。此时模块照样启用（只能观察），停掉工作台的会话后再导入一次即可补上 Key。
- **已启用时。** 本服务已启用 `ondo` 时保留现有设置，只补入缺少的 Key。`secrets.json` 里已有 `ondo` 时不覆盖。
- **没有工作台 Ondo 数据时。** 也能启用，只做观察。
- **入口。**
  - 命令行 `install.sh --import-workbench --ondo`，或 `import-workbench.ts --ondo`；
  - 设置页「从工作台导入」里勾选「启用 Ondo 挂单奖励」。
  - 两种方式导入后都会重启服务。
- **导入后。** 专用永续账户只保留一个实盘写入者。账户级断线撤单会影响同一账户上的其他挂单。

## 9 回退

- v0.62.0 可回到 v0.61.0。停止会话，核清订单和持仓，等待最后一次心跳超过 30 秒，再执行 `sudo bash install.sh --version v0.61.0`。退出设置单独保存在模块设置文件的 `exit` 字段，旧版本仍能读取原有报价参数。回退后再次保存报价设置会移除新退出参数，再升级时采用默认值。

- 回退到 v0.59.0：`install.sh --version v0.59.0`。
- 回退前先删掉 `config.json` 和 `secrets.json` 里的 `ondo`，否则旧版本的配置检查不认这个键，会拒绝启动。
- 如果本服务正在实盘挂单，先在页面停止并确认撤单完成。
