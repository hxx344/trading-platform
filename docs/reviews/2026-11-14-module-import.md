- 日期：2026-11-14
- 范围：见 [docs/module-import.md](../module-import.md)。设置页「从工作台导入」面板与命令行 `install.sh --import-workbench` 新增「启用行情监控」「导入资产账本」；新增 `src/service/import-modules.ts`、`src/asset/import-writer.ts`，`src/asset/import.ts` 拆为读 / 校验 / 写三步。
- 等级：R3（root 导入助手、配置写入、服务重启、往数据目录写库）。一路独立审查（只读，与作者隔离，高风险档）。
- 回滚：`sudo bash install.sh --version v0.12.0`（配置格式与库结构未变，回退后已写入的配置与账本照常读取）。

## 审查结论

无 P0/P1。逐项核实无误：

- 权限边界：读工作台账本以账本属主身份（uid/gid，不带附加组）、空环境子进程只读打开；写 `asset.sqlite` 以数据目录属主身份子进程写入（umask 077，600），root 不直接打开数据目录里的库；属主不对或非普通文件拒绝接管。
- 注入面：用户名规则贯穿页面与命令行，助手再核对其在工作台用户列表内；SQL 全部参数化；参数全部以 argv 传递；工作台内容出口均去控制字符并截断。
- 导入规则不弱化：`prepareLedger` 对传回的行做形状、白名单、重复检查后走原有全部校验；事务整体替换不变；命令行行为与基线一致。
- 顺序：先写账本（失败则什么都不改）→ 配置无变化则不写不重启 → 有变化走原撤销/检查/重启流程，失败恢复配置、账本保留并在消息中说明。
- 页面：校验在服务端逐项严校验，页面不持有唯一校验；默认不勾选；无内联样式；写操作带 `x-pa-executor`。
- 未选新两项时，配对/原油/期权导入路径与基线逐行一致。

| 级别 | 问题 | 处理 |
| --- | --- | --- |
| P2 | 导入助手在账本写入后被中断时，两处中断消息只说“配置未改动 / 已恢复导入前的配置”，不提账本可能已写入 | 已修：三处中断消息补“若勾选了资产账本，账本可能已写入并保留，请在资产页核对” |
