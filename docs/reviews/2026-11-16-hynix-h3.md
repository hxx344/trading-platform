# 海力士分批与价差自动规则（H3，R3）审查记录

- 批次：v0.53.0，方案与实施见 [../hynix.md](../hynix.md) 第 8 节、[../oil.md](../oil.md) 第 7 节。
- 等级：R3（执行器分批规划、自动下单状态机、规则库内容）。

## 影响面与回滚（动手前）

- 用户可见行为：海力士下单可分批；海力士页多「自动开平仓」；原油与海力士规则可分批。不填批数的原油规则与旧版相同。
- 涉及文件：`src/contracts.ts`、`src/executor.ts`、`src/hynix/sizing.ts`、`src/oil/rules.ts`、`src/oil/rule-live.ts`、`src/service/oil.ts`；页面 `web/src/OilRules.tsx`、`oil-rules-form.ts`、`HynixPage.tsx`、`hynix-form.ts`；测试与文档。
- 不碰：数据库结构（`oil-rules.sqlite` 仍为库版本 2，只在规则参数 JSON 里按需多字段）；划转、ADL、期权、资产、行情监控；鉴权边界。
- 失败时：规则参数解析失败的规则不判断、不下单、不能启用；执行器分批规划失败在预览阶段拒绝，不发单。
- 回滚：退到 v0.52.1 及更早前先停用全部海力士规则与分批规则，处理掉其持仓与未结束任务（旧版本读不了这些规则，按“规则参数无法读取”显示）。不分批的原油规则在旧版本上只受基点界限约束，旧版本不读任务的 `endCode`。详见 hynix.md 8.3。

## 独立只读审查（第 1 轮，范围 `8450fc5..be909f9`）

审查者与作者上下文隔离，只读。结论：P0、P1 无。

| 级别 | 发现 | 处理 |
| --- | --- | --- |
| P2 | 规则平仓时持有量（如部分平仓后的剩余）分不成规则批数，预览被拒，规则卡在持仓中 | 已修（2114f15）：平仓意图带 `batches.fit`，执行器从规则批数往下找能分开的最多批数，最少 1 批；只对平仓接受 |
| P2 | 规则分批时后续批次不再对照阈值，盘口变差时仍会按基点界限成交，越过阈值 | 已修（2114f15）：触发时照工作台 `boundsFor` 算每腿阈值界限，意图带市价腿 `priceBound`，执行器与基点界限取较紧者，每批发送前盘口越界即不发送 |
| P2 | 上两条与海力士分批规划缺测试 | 已修：补降批、阈值界限、海力士比例对冲分批的测试 |

## 变基到 v0.52.1（`ef43ec6`，主代理复核冲突解决）

开发期间 main 由另一会话发布了 v0.52.0「两腿名义平衡与一键单腿调平」，占用了 hynix.md 第 7 节与 H2 的名称，本批因此改称 H3、文档顺延为第 8 节（前三个提交标题里的“H2”未改写）。

- `src/service/oil.ts` `oilLoops`（改了逻辑）：原油与海力士盘口循环各自读完后调用同一个 `judge()`，同一时刻只有一轮判断，停服时两个循环都等在途判断结束；海力士持仓循环保留 main 的平衡告警。已核对。
- `src/contracts.ts`：`fit` 与市价腿 `priceBound` 放进 main 新拆出的 `PairIntent`；调平意图由 `parseRebalanceIntent` 固定字段解析，不接受这两个字段（补断言）。已核对。
- `src/executor.ts`：`jobView` 合并 main 的 `rebalance` 与本批的 `endCode`；调平任务走独立的推进与结算，不经过 `guardLead`、`fitBatches`、`tighterBound`，不会带 `endCode`。
- 合约锁两边互斥：调平进行中规则预览得到 `symbol_locked`（等 60 秒，不计失败），反之调平预览被拒。

| 级别 | 发现 | 处理 |
| --- | --- | --- |
| P2 | 规则只记自己开的数量、不读账户持仓：规则持有期间在同一账户「减仓调平」后，规则平仓数量超过持仓被 `close_exceeds_position` 拒绝并计失败，3 次后停用（两腿仍对冲）；「加仓调平」多出的数量规则不平 | 登记：hynix.md 8.2 写明规则持有期间不要在同一账户调平；未改代码 |
