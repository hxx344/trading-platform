# 原油价差自动规则 O2b（实盘模式）审查记录

- 日期：2026-11-14
- 范围：见 [docs/oil.md](../oil.md) 7.3。
  - `src/oil/rule-live.ts`：实盘状态、任务结局、状态防御读取。
  - `src/oil/rules.ts`：触发、复核、待确认重放、任务跟踪、页面操作、库版本 2。
  - `src/executor.ts`：只读的 `confirmedJob`，不改执行器其余行为。
  - `src/service/oil.ts` 与 `src/service/main.ts`：接入执行器，判断不阻塞盘口刷新。
  - `src/http.ts`：追加路由。
  - 原油页「自动开平仓」区块：`web/src/OilRules.tsx`、`web/src/oil-rules-form.ts`。
- 等级：R3，服务器按规则自动下单。独立只读审查，每轮新开审查代理；修复后复核。
- 回滚：
  1. 先在原油页停用全部实盘规则，处理掉自动规则的持仓与未结束任务。
  2. 再执行 `sudo bash install.sh --version v0.21.0`。
  - v0.18.0–v0.21.0 遇到库版本 2 会拒绝打开规则库，只显示规则不可用；下单与任务不受影响。

## 第二轮（复核修复提交 f502df5）

第一轮 P1、P2 全部关闭，P3 除登记项外关闭。复审逐处核对了修订号守卫抛错的后果：
- 判断轮的写入都在同步段，紧跟重读之后。
- 确认前先写待确认，确认后写任务失败时，下一轮用同一请求编号重放，或用只读查询找回原任务。
- 结论：不会重复下单，也不会丢任务。

无 P0/P1/P2。

| 级别 | 问题 | 处理 |
| --- | --- | --- |
| P3 | 判断轮不再被等待后，停服可能在执行器关闭后才返回预览，得到 `writer_lost` 并误计一次失败 | 已修：<br>· 停服时盘口循环等进行中的判断轮结束再退出；运行时先在排空时限内等后台循环，再关执行器。<br>· `writer_lost` 与合约被占同样等待 60 秒、不计失败。<br>· 补测试 |
| P3 | `confirmedJob` 只比会话与命令类型，不比预览编号，和确认的重复判断不一致；`requestStop` 的注释错位 | 已修：同样按摘要比较预览编号；注释移回原处 |
| P3 | 真实执行器的 `confirmedJob` 没有单测；“没有 `mode` 字段的旧规则读成观察”没有用例 | 已补：<br>· `test/executor.test.ts`：查到、为空、换会话、换预览、被停止命令占用。<br>· `test/oil-rules-live.test.ts`：去掉 `mode` 与 `live` 后仍读成观察 |
| 登记 | 未知确认错误仍每 3 秒往服务日志写一行 | 接受：规则页事件已去重；服务日志保留每轮失败，便于排查 |
| 登记 | 停服时已确认、尚未发送的任务，下次启动会被取消成 failed，按新规则计一次失败 | 接受：只计一次，连续 3 次才停用；比重启后静默重试更保守 |

## 第三轮（复核修复提交 d439178）
