# K 线图的缓存与增量传输

本批从 v0.70.0（`7e08efc`）开始，按 R2 审查。原油、海力士、Anthropic、永续合约价差图和 CrossEx 交易终端都已经在服务端保存历史。本次处理打开、切换和刷新图表时，平台向浏览器反复发送相同收盘数据的问题。CrossEx 手动对冲界面也会随两腿盘口请求 K 线，但该界面没有价格图。

固定差异的首轮复核发现，下架后的自动选择可能将旧标的盘口点价带入另一张限价预览。这项修正涉及委托表单，单独按 R3 复核。目标是让合约身份变化时重置旧输入，同时保留正常点选实时盘口的操作。错误复用可能给另一合约带入不合适的价格。验收覆盖下架和同名换身份，核对表单与实际预览参数。回退版本仍为 v0.70.0，交易服务的下单、确认和在途订单处理沿用原路径。

第二轮在恢复时加测了两种服务端仍有旧值的情形。同一目录条目更换原生市场时，准备委托所用的盘口、报价和异步回调须随旧订阅失效，交易终端等新身份取得有效盘口后才能再次点价。断开后重新收到 HTTP 应答，未收盘柱也要有新的行情采集依据才能出现。前者继续按 R3 验证，后者按 R2 验证，同时核对正常读取的连续性。沿用上述回退版本。

另一个入口是已打开的限价预览。原生单位改变后，用户点「重新预览」会再次提交旧价格；首次点价与第一次预览之间也有相同的时间差。本批在终端的直接委托预览中携带看到的合约身份，在服务端实时解析合约后核对。验收覆盖单位改变后的首次预览和重新预览、身份吻合的正常预览，以及既有调用方的兼容性。

## 实施范围

按 UTC 时间分段，为每段已收盘的公开价格计算内容版本。页面保留已取得的段，向平台登记已有版本。平台返回当前窗口及其版本清单，新增价格、历史缺口和已修订的收盘按时间合并。服务端重启后，内容相同的段仍可复用。窗口移出的数据和已消失的记录须以本次清单为准。

页面内存负责切换时的读取，浏览器 IndexedDB 保留有限份已核实的公开历史，用于刷新页面后恢复。恢复沿用源数据原有的时间和身份，缺段保持断点。各图表继续沿用原来的坐标、单位、指标预热范围和移动端布局。当前柱、实时盘口、下单预览和在途订单沿用各自的实时数据源。

错误复用可能混入其他周期或合约的数据，也可能让价格修订无法显示。验证将覆盖方向与周期切换、同名合约身份变化、迟到修订、旧缺口、缓存损坏及服务不可用。已有读取接口保留完整快照格式。可以用 `sudo bash install.sh --version v0.70.0` 回退，原有服务端数据库和配置继续使用。

## 已验证的行为

- 三个价差面板的近期确认只保存在当前页面会话内，到下一根收盘或一分钟后重新核实。Chrome 在替身原油服务首次收到 2,729 行，手动刷新收到 0 行，扩大时间范围只收到另外 150 行。从一月缩回一周、从海力士切回原油均发出 0 次 K 线请求。整页刷新原油和 Anthropic 时核对内容版本，均收到 0 行历史。扩大范围等待应答期间，原时间范围的图和统计仍可见。
- CrossEx 同一合约首次回复 239 根已收盘和 1 根当前柱，共 28,120 字节。整页刷新使用 1,695 字节应答核实身份和版本，已收盘行数为 0。切换对冲页后，两腿盘口都继续更新，历史读取器调用为 0。删除浏览器本地记录后能重新取得 239 根收盘柱。
- 合约价差图首次各收到 720 根小时收盘。3、7、30 天切换与多空互换合计发出 0 次成交价历史请求，重开及刷新页面每腿回传 0 行。仅清空替身服务端缓存并重启，双方仍按已核实的覆盖交接旧记录。已经扫描过的空时段、改价和滚出 30 天的记录均以服务端为准。对永久无成交的小时，每次限量轮换回补。
- Windows Chrome 在 1280 和 390 像素宽度检查图表、窗口切换与来源状态。浏览器缓存的一项价格被改坏后，页面舍弃该条缓存并从平台恢复。单独阻塞 IndexedDB 时约 1.2 秒回退，迟到的数据库读取没有覆盖更新或清除操作。使用替身交易所和隔离的数据库，无实盘账户参与。

## 独立审查与修复

两路只读审查分别核对了 `7e08efc` 到代码树 `b77de17` 的公共缓存与交易终端，以及到 `c77b2bd` 的三个价差面板与永续小时线。首轮发现以下问题。

- CrossEx 有三项 P1。升级时合约目录里的非空字段会导致旧 SQLite 归档无法命中，恢复使用原生合约键后，新旧版本能互读同一归档。目录下架时自动换约可能把盘口选价带到另一张限价单，现由用户重新选择，每张表单独立绑定目录和原生合约身份。暂停读取时当前柱可能跨周期残留，现于停读时移除，等下一次有效应答再显示。
- 永续价差有两项 P1。服务重建只返回最近 72 小时时，之前缓存的小时线可能在不相连的时间段和 UTC 日边界丢失。现在逐小时保留仍在 30 天内且未重查的原记录，并沿用原始内容版本；服务已核查的小时以当次结果为准。相隔七天和一天恢复时，分别保住 552 和 648 根旧柱。历史缺口超时原先会推进游标并等待六小时，现按短退避重试，成功才推进。另有一项 P2，明确拒绝访问的 401、403、404、423 现在会清除两腿的缓存和图表，503 仍可展示上次历史。
- 安全差异扫描插件对本机 Git 工作区返回无法解析 HEAD，未生成扫描报告。委托表单与公开缓存的边界同时纳入本地独立代码复核。未连接真实交易所或账户，未向服务器部署。

第二轮复核的生产代码树为 `a2d5102`。CrossEx 下架后的表单重置及 v0.70.0 归档双向兼容通过。复核发现一项 P0 和两项 P1：父组件可能用旧选价重新预览已经换单位的合约，旧 WebSocket 盘口也可能在同名新市场下重新出现，恢复连接的应答还可能带入停读前的当前柱。终端现在向预览传递点价时的合约身份，服务端核实当前目录与原生身份，换代时撤销旧订阅，只接受新代次的行情。未收盘柱单独核实采集时间。Chrome 使用真实终端与预览业务代码，验证了旧价 100 被拒绝、换代后新盘口 20 可以预览，以及重新采到相同价格后当前柱恢复。

永续小时线与公共缓存的第二轮发现两项 P1 和一项 P2。首份应答已经扫完近 72 小时、补旧页随即失败时，须接纳已扫部分，保留范围外旧价格。403 清除请求遇到 IndexedDB 打开超时时，删除须等待事务提交，期间重新载入页面也不能恢复旧值。当没有可展示的历史且读取失败时，图表状态同步显示失败。新增回归包含完整 30 天缓存恢复、慢打开与重新授权。Windows Chrome 实测约 1.2 秒后前台恢复响应，未完成删除时硬刷新仍读取不到旧价，重新取得的有效价格可正常落盘。

第三轮在代码树 `1b108e8` 复现了三个跨组件问题。共享深度读取器能将旧目录版本的在途应答交给新版终端，已生成的直接委托计划在确认时只核对原生身份，切换到订单页再返回会失去未收盘柱的上次采集时间。暂停原方案后，重新对齐以下边界：共享深度须按同一目录及原生身份复用；已绑定身份的直接预览把该身份带入最终实时复核；未收盘柱的采集时间跨页面卸载保留，恢复时继续等待下一次采集。核验以真实共享读取器、预览确认业务方法和页面重挂为准。旧版直接预览依然使用其原有校验。回退用 v0.70.0 和原有数据目录。

同轮用两个 Chrome 页签复现两项缓存 P1。旧页迟到的删除可误删另一页刚确认的新值，localStorage 配额用尽时也无法新增失效标记。公共缓存改为在写入有效行情时预先登记每条记录的版本，恢复前比对登记版本与 IndexedDB 行。拒绝访问只需撤销已有版本。迟到的清理在读写事务内核对当前版本，保留另一页已经正式写入的数据。无法登记版本时，本次有效行情可在内存中继续使用。

Windows 原生检查覆盖 `pnpm check`、`pnpm build:web`、公共分段及三个监控面板的定向测试、永续小时历史、CrossEx 终端和手动委托预览、共享深度和容量计算。用 v0.70.0 标签里的真实读取器先写 SQLite 归档，新版离线读回、新增一根后再用原版离线读回。Chrome 同源多页实测把存储配额填满、将一页的数据库打开推迟 1.2 秒，在撤销版本后重开两腿均无旧价；另一页重新取得的两条 444 在迟到删除和硬刷新后均可读。

公共缓存增量在固定树 `5e8df7e` 完成独立复核，两项 P1 均关闭。复核使用实际磁盘上的 Chrome 配置，分别在 403 和 404 后关闭并重启浏览器，并以 503 验证恢复结果。

在固定树 `0fae556` 的替身复核中，直接预览等待深度时，另一次原生查询已经确认同名合约单位从 1 改成 2，但写前校验仍引用先前查询保存的单位 1。按 P0 重新对齐确认链：市场应共享每个合约最近已核实的原生身份，迟到查询不能覆盖较新证据。等待盘口和实际写前都要与该状态及现行目录比较。检查范围限于持有身份绑定的直接预览，同一身份正常刷新继续有效。

同一原生状态也影响容量与终端的在途深度，按 P1 一并修正。该轮已独立验证真实 React 终端切到订单页再返回：重复的采集时间只显示已收盘历史，后来采到相同的交易价格时当前柱正常恢复。永久归档键和浏览器内容版本保持跨进程稳定，服务端代次仅用于仍在途的行情读取和短时预览。

此项补正后的 CrossEx 行情、预览与共享深度定向回归共 76 项通过。另在 Windows 运行整个 `test/crossex-service.test.ts` 时，有 6 项依赖 Linux 的账户进程锁、2 项依赖 POSIX 的 0600 文件权限而失败。这 8 项以本次正式发布的 Ubuntu 主线 CI 为验收环境。

在代码树 `528e22e` 上，终端和持仓资金费通过同一条原生读取路径登记身份证据。独立复核分别用 Gate 数量单位和 Lighter 市场编号核对了同一身份、等待中的旧读、换代后再换回、迟到的资金费应答和旧格式预览。真实容量入口在读取风险或杠杆期间换代后会丢弃旧结果。没有 Gate 目录的持仓仍能取得原生资金费，目录网络请求为 0。

最后补测了 Gate 目录查询本身也在等待的情形。终端先等目录时，持仓资金费可以先发出原生查询，此时须按真正发出原生查询的顺序登记版本。旧实现先给整次终端请求编号，实测会保留单位 1、拒绝本应生效的单位 2。现在在发出原生请求前编号，新增的回归能正确接受单位 2，原有选价和预览的写前校验同时失效。

最终增量的代码树为 `520d81c`。Windows 行情业务回归 37 项全部通过，独立复核再次运行了目录等待及持仓资金费两种次序。至此 P0、P1、P2 各 0 项。
