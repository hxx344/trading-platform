审查当前改动。全程只读，不修改文件、不提交。

审查范围：$ARGUMENTS

1. 读取 `AGENTS.md` 与 `docs/code-review.md`。
2. 确认审查范围：
   - 指定提交、分支或 PR 时，只审指定差异。
   - 未指定时审查当前工作区。用 `git status --short --untracked-files=all` 列出文件，用 `git diff HEAD` 查看已跟踪文件的改动，并逐个读取 `??` 文件。无法判断哪些文件属于本次改动时，在结论里列出并说明按哪些审了。
3. 按 `AGENTS.md` 的《按改动取用经验》只读改动涉及的 `LESSONS.md` 条目，作为意见依据；并读改动所属模块的文档（`docs/` 下对应文件）。
4. 按 `docs/code-review.md` 第 2 节判定风险等级，按 D1–D7 顺序审查：先语义与正确性，再失败路径，最后细节。
5. 意见格式照 `docs/code-review.md`《独立审查》：一条一议，同一根因的多个位置合并为一条；给不出复现路径的按该文件第 3 节标「待核实」，不按 P1 阻塞。
6. 末尾给结论：是否满足合并门槛、P0/P1 数量、哪些检查没有覆盖（不要声称运行了未运行的测试）。

本技能以独立子代理运行，满足 `docs/code-review.md`「审查者的上下文与作者隔离」。R3 改动需要更深的资金与执行方向审查时，作者另用 `r3-reviewer` 子代理。
