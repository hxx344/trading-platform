# 历史行情与交易记录增量读取

2026-11-19。本批从主线 `5a53bd7` 开始，交付时已包含 v0.69.1（`518469a`）的只读令牌和执行器诊断。按 R3 审查，涉及账户历史、持仓盈亏的依据和模块数据库。

## 目标与影响

价差监控、交易所对比和 CrossEx 终端从本地保存的已收盘 K 线、已结算资金费恢复，只向交易所补新时段、缺失数据和必要的迟到记录。资产持仓盈亏、CrossEx 流水和期权任务使用本地已核实的交易记录，账户身份、凭据版本、合约及时间范围均参与复用判断。

公开行情进程按执行端提供的历史区间读取，上游失败、数据不完整或落盘失败时保留原进度。新增缓存须兼容已有数据库。历史展示保留来源时间和缺口，当前盘口、委托受理、撤单和在途状态继续经原有实时路径核实。

## 失败与回退

缓存与账户错配会算错盈亏，漏页或错误推进进度会掩盖成交和结算缺口。本批验证跨重启、缺页、迟到、异常、身份切换及实时查询隔离。使用 `sudo bash install.sh --version v0.69.1` 可回到上个正式版本。新表及旧表新增的 JSON 字段由旧版忽略，保留原配置、订单及历史数据。

第二轮固定增量 `5eab6a4a`、`7b460471`。复核发现回拨跨周期重启会隐藏库中的收盘，及预热的成交展示可能在另一入口撤权后保留。CrossEx 已按本地时钟重新装入刚恢复可见的收盘，并用索引读取该合约周期的最高观测时间。替身归档的 239 根在时钟追平后全部可见，覆盖上游只给当前柱、返回空和读取失败。恢复中的期权委托在收益循环实时补成交，委托终态仍由订单查询独立确认。

账户权限复核以 `4cae74e0` 证实了只读库以及删除事务锁忙的恢复问题。重新对齐私有缓存的条件：未经本进程确认的凭据不能仅凭本地留存的成交记录恢复授权。权限校验覆盖同账户、同凭据版本的市场和服务，网络失败不能解除已知拒绝。清除持久记录和内存快照仍属于撤权处理，但落盘失败不能成为显示旧成交的理由。
